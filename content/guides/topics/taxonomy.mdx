The Taxonomy seam holds two systems that grew up together. **Taxonomies** group content: categories, tags and any a
plugin registers. The **Metadata API** stores named values for posts, users, terms and comments alike. This guide
explains how each is put together. For using a taxonomy in a plugin, read
[Grouping content with taxonomies](/guides/path/grouping-content-with-taxonomies/) first.

## Three tables behind every taxonomy

A term is spread over three tables, and knowing why explains several functions' arguments.

- `terms` holds the term itself: its name and slug.
- `term_taxonomy` places a term in one taxonomy, with its description, its parent and a count of the objects it
  groups. A term's place in a taxonomy has an ID of its own, the `term_taxonomy_id`.
- `term_relationships` links objects, usually posts, to those places.

That is why <Sym id="function:wp_insert_term" /> returns two IDs, and why some functions ask for a `term_taxonomy_id`
rather than a term ID. A taxonomy itself isn't stored at all. It exists while the code that registers it runs.

## One metadata API for every object

Post meta, user meta, term meta and comment meta are four tables with the same shape, and one set of functions
serves them all, taking the kind of object as the first argument. `get_post_meta()` is a thin wrapper around
`get_metadata( 'post', … )`, and the others are the same. So the rules below hold for every kind of meta.

<Sym id="function:add_metadata" /> adds a value. A key may hold several values, unless you ask for it to be unique.
Arrays and objects are stored serialized:

<Sym id="function:get_metadata" /> returns every key, one key's values, or the first value. A missing key gives the
registered default, or an empty string (or an empty array) when there is none:

<Sym id="function:update_metadata" /> changes values, and can be limited to rows holding a previous value.
<Sym id="function:delete_metadata" /> removes them, for one object or, with `delete_all`, for every object at once:

<Example id="taxonomy/update_metadata/update" />
