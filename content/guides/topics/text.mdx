title: Formatting and kses
summary: How escaping, sanitizing, kses and the content formatters fit together, and where each runs in a request.
---

The Text seam holds the functions that change strings: escaping them for output, sanitizing them for storage,
filtering their HTML through **kses**, and formatting post content for display. They look alike, and many take a
string and return a string, but they answer different questions at different moments. Using the wrong one for the
moment is the most common way plugins go wrong. This guide sorts them out. Each function's reference page has the
details.

## Three jobs, three moments

- **Sanitizing** happens on the way in, before a value is stored. It makes the value fit its field: plain text, a
  key, a slug, a file name. It changes the value.
- **Escaping** happens on the way out, at the moment of printing. It makes the value harmless for one place in the
  page, such as text, an attribute, a URL or a script string. It never changes what is stored.
- **Kses** sits between them. It filters HTML down to a list of allowed tags, attributes and protocols, so
  people can use some markup and no more. WordPress runs it when content is saved, and plugins run it whenever they
  print HTML they didn't write.

[Keeping your plugin safe](/guides/path/keeping-your-plugin-safe/) puts these to work in a plugin. Here is how the
pieces of each family differ.

### When WordPress runs kses itself

WordPress applies kses to posts, excerpts and comments as they are saved, through filters such as `content_save_pre`.
It does this only for people without the `unfiltered_html` capability, which on a single site means everyone except
administrators and editors:

<Example id="guides/text/kses-on-save" />

The author's script and `onclick` were removed when the post was saved. The administrator's were kept, on purpose:
administrators may embed anything. That is why your plugin still escapes or filters post content it prints in a new
context. Content was cleaned for the person who wrote it, not for the place you are putting it.

## Formatting post content

Post content is stored as written and formatted each time it is shown, by the filters on the `the_content` hook. In
order: blocks are rendered, <Sym id="function:wptexturize" /> turns straight quotes and dashes into typographic ones,
<Sym id="function:wpautop" /> turns blank lines into paragraphs, and shortcodes run after that.

<Sym id="function:wp_trim_words" /> shortens text to a number of words for excerpts and previews, removing tags first:

Run your own output through `the_content` only when it really is post content. Applying the filter to anything else
runs every plugin's content callbacks on it too.

The Text seam isn't ported to SpeedySpec yet, so this guide makes no promise about how these functions behave there.
