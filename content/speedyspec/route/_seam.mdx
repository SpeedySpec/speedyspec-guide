Not native yet: speedyspec-server has a Rust port of the Rewrite API, but the runtime worker doesn't link it, so PHP still gets WordPress's own `rewrite.php`, `WP_Rewrite` and the rest of this seam. <Ev source="ss:crates/speedyspec-php-runtime/Cargo.toml#L24-L61" hash="6f4cc0a8bd36744bf5405190b45effa2b6e7bf0dc07102a16609d3f7a8def695"/>

The port covers 10 of the seam's 23 functions and 2 of its 4 classes: `add_rewrite_rule`, `add_rewrite_tag`, `remove_rewrite_tag`, `add_permastruct`, `remove_permastruct`, `add_feed`, `flush_rewrite_rules`, `add_rewrite_endpoint` and `_wp_filter_taxonomy_base`, with `WP_Rewrite` and `WP_MatchesMapRegex`, and 7.2's `wp_flush_rewrite_rules_on_site_language_change()`, which the facade declares with WordPress's own one-line PHP body. <Ev source="ss:crates/speedyspec-wp-rewrite-php/src/rewrite.php#L841-L850" hash="487385c1cd5efeedd47b18942a4d926505859e98f8cbb67c19e6da88fb13c6af"/> <Ev source="ss:crates/speedyspec-wp-rewrite-php/src/rewrite.php#L704-L782" hash="cfd9f5321658ed7e34f3fc7da9127f8963014d509caa418cee0a58ae7dd5b91f"/> Request matching, `WP::parse_request()`'s rule loop, is ported too, but `parse_request()` belongs to the Query seam. <Ev test="speedyspec-router-presentation::subject::requested_path_matches_parse_request"/>

How it's checked:

- **Recorded scenarios.** 34 scenarios recorded from WordPress 7.2-RC2 replay through the port, so each compares 7.2's `random_base` property and its stored random content rules too: eight permalink structures, a subdirectory install, each endpoint mask, extra and external rules, tags and permastructs, `add_feed`, the rule filters and actions, `WP_Rewrite`'s getters and setters, property writes, and rules generated on first read. `compat/rewrite/breaks.json` lists no breaks. <Ev area="rewrite" scenario="structure_postname"/> <Ev area="rewrite" scenario="endpoint_all"/> <Ev area="rewrite" scenario="tags_and_permastructs"/> <Ev area="rewrite" scenario="filters_and_actions"/> <Ev area="rewrite" scenario="getters_and_setters"/> <Ev source="ss:compat/rewrite/breaks.json#L1-L3" hash="40822ffa4a111618f7fe206d1e38b141b2653eaa13c3ec3bba56f3987f5b263e"/>
- **WordPress's PHPUnit tests.** Four of WordPress's rewrite test files run against the port: `addRewriteRule.php`, `addRewriteEndpoint.php`, `permastructs.php` and `rewriteTags.php`, less three endpoint tests that visit posts. None is marked as a documented break. <Ev test="speedyspec-wp-rewrite-php::wordpress::wordpress_rewrite_tests_pass"/> <Ev test="speedyspec-wp-rewrite-php::wordpress::documented_breaks_are_listed"/> <Ev source="ss:crates/speedyspec-wp-rewrite-php/tests/wordpress.rs#L19-L24" hash="571555f4c03aaec3328fffb4db26fee6449e51cebdfc4c432daf81d2ee5e442f"/>
- **Not run:** `rewrite.php`, `numericSlugs.php`, `oldDateRedirect.php`, `oldSlugRedirect.php` and `wpResolveNumericSlugConflicts.php`. They create and visit posts, which needs the posts and `WP_Query` ports; the test's bootstrap, `tests/php/rewrite-bootstrap.php`, says what is run and why. <Ev source="ss:crates/speedyspec-wp-rewrite-php/tests/wordpress.rs#L1-L4" hash="981b876e72efb956d34f9423c4db100e16683a3d20bdb6e9ed0e20e1ddddccd9"/>

- **Random content redirects (7.2).** `WP_Rewrite::random_rewrite_rules()`, `set_random_base()`, `get_random_base()`, `post_permalinks_share_random_base()`, the `$random_base` property and the `random_rewrite_rules` filter are ported. Five generation cases recorded from 7.2-RC2 replay, and checks through PHP cover a translated base, the rules for authors, taxonomies and post types, both filters, and an exception thrown in a filter coming out unchanged. What these read from unported areas (post types, taxonomies, page lookups, query.php's switch, translations) PHP answers through outbound ports. What the port doesn't cover: `canonical.php` (`redirect_canonical()` and its helpers), `url_to_postid()`, `wp_resolve_numeric_slug_conflicts()` (the replay loads WordPress's own), the rest of random content (`WP::handle_random()` and the query filters, in the Query seam), speculative loading (`WP_Speculation_Rules` and its functions) and `WP_URL_Pattern_Prefixer`. <Ev source="ss:compat/rewrite/setup.php#L36-L37" hash="bc43fe3d030e5905cc13c4f2911db86af25fd67a14cdfb3978b7fc86c77396ad"/>
