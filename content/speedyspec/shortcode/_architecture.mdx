## The crates

- **`speedyspec-wp-shortcode-contracts`** holds the plain values (`TagName`, `TagSet`, `ParsedAtts`, `ShortcodeMatch`), the ports and strategy traits, and WordPress's pattern strings (`get_shortcode_regex()`, `get_shortcode_atts_regex()`), which plugins and `wptexturize()` rely on byte for byte. <Ev source="ss:crates/speedyspec-wp-shortcode-contracts/src/lib.rs#L5-L13" hash="cba235c1e8863031f563c0ba944859681ea0bc195ca0002a252a318b0254e13b"/>
- **`speedyspec-wp-shortcode`** holds `ShortcodeApi`, one method per function in `shortcodes.php`, the scanners and attribute parsers, `MemoryRegistry`, `HookApiFilters`, `NoFilters` and the use-case messages. It has no PHP. <Ev source="ss:crates/speedyspec-wp-shortcode/src/api.rs#L13-L30" hash="0ab0143fba5300af0107b50b9da3eb588e8ee68c8edf9e887bfd451c84c6a26b"/>
- **`speedyspec-wp-shortcode-php`** holds `ShortcodeArea`: the PHP functions as one-line shims over native functions, `PhpGlobalRegistry` over `$shortcode_tags`, `PhpShortcodeHandler` for PHP callables, and adapters onto `wp_html_split()`'s Rust port, the kses port and WordPress's `_doing_it_wrong()`. <Ev source="ss:crates/speedyspec-wp-shortcode-php/src/lib.rs#L1-L13" hash="30b54a35b663887df1ce94a5f858834971f5cd2e253e3479bae49dd22363f217"/>

## The use cases

Every function is a message on `speedyspec-cqrs`'s buses: three commands (`AddShortcode`, `RemoveShortcode`, `RemoveAllShortcodes`) and thirteen queries (`DoShortcode`, `ShortcodeAtts`, `StripShortcodes` and the rest). Each is bound in the container under `SpeedySpec\WpShortcode\<Message>Handler`, with `ShortcodeApi` as the handler. <Ev source="ss:crates/speedyspec-wp-shortcode/src/messages.rs#L53-L91" hash="cff0289072b9145027410a9d655533ad0eae90f97e802270c70c365ebc589fa3"/> <Ev test="speedyspec-wp-shortcode::filters::messages_dispatch"/>

## The adapters

- **Registry:** `PhpGlobalRegistry` keeps the `$shortcode_tags` global itself, so code that reads or swaps the array sees the same thing WordPress shows. `MemoryRegistry` is for Rust-only use. <Ev test="speedyspec-wp-shortcode-php::php::case_global_is_registry"/> <Ev test="speedyspec-wp-shortcode-php::php::case_embed_swap"/>
- **Handlers:** a PHP callable runs through `PhpShortcodeHandler`. A Rust handler is declared as a native PHP function with `ShortcodeArea::register_rust_handler()`, so `$shortcode_tags` holds its name as it would in WordPress. <Ev source="ss:crates/speedyspec-wp-shortcode-php/src/lib.rs#L95-L102" hash="213d4abf937e7d8c1767643649cb52a013c67c88c6e7e1859da6167f4472842d"/> <Ev test="speedyspec-wp-shortcode-php::php::case_rust_handler_name"/>
- **Filters:** `HookApiFilters` over the Rust Hook API; `NoFilters` when nothing listens.
- **HTML and kses:** `RustHtmlSplitter` and `RustKsesAttributes`, so `wp_html_split()` is never a PHP call. <Ev test="speedyspec-wp-shortcode-php::php::case_html_split_is_rust"/>
- **Notices and string conversion** still go to WordPress's PHP (`legacy`). <Ev test="speedyspec-wp-shortcode-php::php::case_doing_it_wrong"/>

`ShortcodeArea::new()` wires these together; `with_strategies()` takes another scanner and parser. <Ev source="ss:crates/speedyspec-wp-shortcode-php/src/lib.rs#L65-L93" hash="4b03bdff6a3b9f8d2cfd606b9c4cb88300a6213018a3b909ce8a02c6e40848be"/> To replace one use case, bind its handler key again, from Rust or from PHP through the container.

## Patterns

- **Facade:** `ShortcodeApi`, and the PHP functions over it.
- **Command and Query:** a message per function, bound in the container (**Registry**).
- **Strategy:** the scanner (`HandScanner` by default, `FancyRegexScanner` as the reference) and the attribute parser (`HandAttsParser`, `RegexAttsParser`).
- **Iterator:** a scan yields matches lazily and holds no borrow, so handlers can re-enter the API. <Ev test="speedyspec-wp-shortcode::api::handler_reenters"/>
- **Adapter** for the PHP registry, handlers, filters, kses and HTML splitting; **Null Object** for `NoFilters`; **Value Object** for tags and parsed attributes.

## Calling it from Rust

```rust
use std::rc::Rc;

use speedyspec_container::Container;
use speedyspec_cqrs::QueryBus;
use speedyspec_wp_shortcode::DoShortcode;

/// Expands the shortcodes in a stored excerpt, or returns it unchanged when a handler fails.
fn expand_excerpt(container: Rc<Container>, excerpt: &[u8]) -> Vec<u8> {
    let queries = QueryBus::new(container);
    match queries.ask(DoShortcode { content: excerpt.to_vec(), ignore_html: false }) {
        Ok(Ok(html)) => html,
        _ => excerpt.to_vec(),
    }
}
```

## How to change this

- **What must pass:** the crates' own tests; the recorded scenarios in `compat/shortcode`, replayed by `speedyspec-wp-shortcode-php`'s `compat` test through every scanner and parser; and WordPress's shortcode tests, run by its `wordpress` test. <Ev test="speedyspec-wp-shortcode-php::wordpress::wordpress_shortcode_tests_pass"/>
- **Recording a new scenario:** add it to `compat/shortcode/scenarios.json` and run `cargo run -p speedyspec-compat -- record shortcode --wordpress 7.2-RC2` (the pin in `compat/wordpress.json`); a difference the port can't match goes in `breaks.json` with its reason.
- **Linking it into the runtime** means adding the area to the worker and preparing WordPress's files so its `shortcodes.php` doesn't declare the functions twice. <Ev source="ss:crates/speedyspec-wp-theme-json/README.md#L101-L103" hash="67bfdcd9955266fb5c1444fca27ae3b3eb8ecb89145ed55ca3509428bd7e493d"/>
