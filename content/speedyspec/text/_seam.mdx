Ported in Rust, not yet in the runtime. speedyspec-server has a Rust port of kses and of most of `formatting.php`, with PHP areas that declare WordPress's functions over it, but the runtime worker links neither crate, so PHP code on SpeedySpec still calls WordPress's own `kses.php` and `formatting.php`. <Ev source="ss:crates/speedyspec-php-runtime/Cargo.toml#L20-L55" hash="955f1ccec24cc11da3fa0826db96868561c6e6c3cdc55277b37b80c09b513508"/> Everything below is what the port's own tests prove, not what the runtime serves today.

## What the port covers

The seam has 171 WordPress functions: 121 in `formatting.php`, 48 in `kses.php`, and two deprecated ones (`addslashes_gpc()`, `wp_kses_html_error()`). The port's PHP areas declare 125 of them natively.

- **kses: 45 of `kses.php`'s 48 functions** (and `wp_allowed_protocols()`, from the Support seam). Left as WordPress's PHP: `wp_sanitize_html_kses()` (7.2's HTML API sanitizer, which `wp_kses()` hands off to), `_wp_kses_sanitize_note_mention_classes()` (it needs the HTML API's tag processor) and `wp_filter_global_styles_post()` (it needs the theme.json port). `wp_kses_html_error()`, deprecated in 7.2, is no longer declared: it lives in `deprecated.php`. <Ev source="ss:crates/speedyspec-wp-kses-php/src/release.rs#L8-L12" hash="ab42954e72fd70949ce0b4e1a7ec5718a833ca65682ad71513f6dc962de3bed0"/>
- **`wp_kses()` has two paths.** WordPress 7.2 sends it to `wp_sanitize_html_kses()` unless the `wp_kses_force_legacy_parser` filter answers true, and stock 7.2 makes it answer false. The port follows: the HTML API path, the default, is WordPress's PHP; only the legacy path is native. See [wp_kses](/speedyspec/text/wp_kses/). <Ev source="wp:wp-includes/default-filters.php#L309" hash="3afd5859a532625abacaf2c9ac91609821ef80bed6c17ca077929d83af89754a"/>
- **Formatting: 80 of `formatting.php`'s 121 functions**: the escapers (`esc_html`, `esc_attr`, `esc_js`, `esc_xml`, `esc_textarea`, `_wp_specialchars`, …), the content filters (`wptexturize`, `wpautop`, `shortcode_unautop`, `convert_smilies`, `make_clickable`, …), the sanitizers (`sanitize_title`, `sanitize_file_name`, `sanitize_text_field`, `sanitize_email`, …), 7.2's `wp_truncate_slug` (see [wp_truncate_slug](/speedyspec/text/wp_truncate_slug/)), `esc_url` and the link functions, and `wp_html_split`. <Ev source="ss:crates/speedyspec-wp-text-php/src/release.rs#L7-L9" hash="60af55a4fedc07a0ccb15cb59ea70d20cd07c538a0abd7acc044cc764de871ce"/> The rest stay WordPress's PHP, among them `esc_sql()`, `sanitize_option()`, `map_deep()` and the `*_deep()` functions, the date functions, the emoji functions and `wp_trim_excerpt()`. Two follow changes WordPress 7.2 made: `sanitize_locale_name()` returns `''` for a value that isn't a string, without its filter, and `wp_pre_kses_less_than()` changes nothing unless `$wp_kses_operating_mode` is `legacy` (unset counts as legacy). <Ev source="ss:crates/speedyspec-wp-text-php/src/native.rs#L437-L440" hash="1674ef592ab25d23f55191db94fad49a262057f309cafa63173b34b1d58c63d4"/> <Ev source="ss:crates/speedyspec-wp-text-php/src/native.rs#L500-L503" hash="8ee901a43ae29c6ee8f15b8b384cbcf365d0a1c38671a2a2e1f3168bcc68989c"/> The Rust crate has cores for several `*_deep()` functions, checked against the corpus, but PHP keeps WordPress's, which walk object properties. <Ev source="ss:crates/speedyspec-wp-text-php/src/native.rs#L273-L274" hash="5aa55138a19c7d80ec8dd66239a56b1460fe02d662b727b531237ff1966d4be4"/>

## The evidence

- **kses: 46 recorded scenarios** from WordPress 7.2-RC2 replay through the native functions with the same results, hook invocations and hook globals. 26 take the legacy path: every allowlist context, the post and data functions, entities, protocols, the kses filters and plugins writing the allowlist globals. The other 20, `html_api_*`, turn the legacy parser off first, as stock 7.2 does, so they prove the hand-off to WordPress's PHP sanitizer, not native code. <Ev area="kses" scenario="kses_every_context"/> <Ev area="kses" scenario="globals_written_by_plugins"/> <Ev area="kses" scenario="html_api_kses_every_context"/> <Ev source="ss:crates/speedyspec-wp-kses-php/tests/compat.rs#L62" hash="dee32562acaadeb9da77c519dbc05fe80c3cd320be1ec484dd212d339a612835"/>
- **kses: WordPress's own kses tests** (at least 395 test cases) pass against the native functions, with no documented breaks. They assert the legacy parser's output. <Ev test="speedyspec-wp-kses-php::wordpress::wordpress_kses_tests_pass"/> <Ev test="speedyspec-wp-kses-php::wordpress::documented_breaks_are_listed"/> Every Rust function is also compared with WordPress's `kses.php` over a corpus, and no exploit in the attack corpus survives. <Ev test="speedyspec-wp-kses::differential::corpus_matches_php"/> <Ev test="speedyspec-wp-kses::security::no_exploit_survives_kses"/>

## Documented differences

- **kses** never does runaway work: a token that doesn't settle after 16 passes is dropped, and the nested passes of one `wp_kses()` call have a work budget. A malformed allowlist rule or `wp_kses_uri_attributes` filter fails closed where WordPress throws a `TypeError`. <Ev area="kses" break="kses:never-settling-token"/> <Ev area="kses" break="kses:nested-work-budget"/> <Ev area="kses" break="attribute_rules_malformed_tag_values"/> <Ev area="kses" break="kses:uri-attributes-not-an-array"/>
- **Escaping** treats the East Asian multibyte charsets as single-byte, where PHP's `htmlspecialchars()` returns `''` for an invalid sequence. <Ev area="formatting" break="htmlspecialchars/literal/charset_sjis_invalid"/>
- **PCRE limits**: on pathological input, a pattern that exhausts PHP's backtrack limit (so WordPress sees no match) still matches in the port. <Ev area="formatting" break="force_balance_tags/literal/balance_backtrack_18"/> <Ev area="formatting" break="esc_xml/literal/xml_cdata_backtrack"/>
- **Bad filter values**: where a `no_texturize_tags` filter returns a non-array, WordPress throws and the port texturizes. <Ev area="formatting" break="wptexturize/unrecorded/no_texturize_list_not_array"/>
- **Engine behaviour**: the natives raise no PHP 8.1 null deprecations, cast an array argument as `(string)` does instead of throwing, take arguments by position only, and run formatting callbacks added by name with no PHP frame. <Ev source="ss:compat/formatting/breaks.json#L54-L75" hash="227f8e7ddbe7789752bd2d01d678786ba5c923f0235cd80066cf2a9099c9d0b1"/>
