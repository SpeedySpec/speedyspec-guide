## The crates

- **`speedyspec-wp-options`** is `option.php` in Rust. `OptionsApi` holds the option functions, `NetworkOptionsApi` the site and network options, `TransientsApi` the transients and `SettingsRegistry` the registered settings. The option entity, `Option`, is a plain object; `SerializedValue` is the `option_value` column as stored. It holds no PHP. <Ev source="ss:crates/speedyspec-wp-options/src/lib.rs#L1" hash="9da2f5a1229021d245418eaf69a0aa0187e28b12f5a63abc84a4a308526f3a38"/> <Ev source="ss:crates/speedyspec-wp-options/src/entity.rs#L1" hash="b2339b5440942a9e4d5b346bf86415f434e8ac4cf39c6fa5b8f98ece5644f30d"/>
- **`speedyspec-wp-options-sql`** is the option repository over `wp_options`, the sitemeta repository over `wp_sitemeta`, and the expired-transient purge, all through the Rust `wpdb`, so the `query` filter fires and `$wpdb->num_queries` counts each statement. <Ev source="ss:crates/speedyspec-wp-options-sql/src/lib.rs#L1-L3" hash="e93d8ca80995437e109c88aab4c23f0172995defed4ccdc540bfe989d7e83cbf"/> <Ev test="speedyspec-wp-options-sql::mysql::query_fires_and_counts"/>
- **`speedyspec-wp-options-memory`** is an in-memory repository, for tests and for callers without a database. It answers as MySQL does, row counts included. <Ev source="ss:crates/speedyspec-wp-options-memory/src/lib.rs#L1-L2" hash="38e2b235063b276161574d36544d23177eb500c8706dcde127403b91606f21cd"/>
- **`speedyspec-wp-options-php`** is the PHP area, `OptionsArea`: it builds the APIs with the SQL repositories and the PHP adapters, registers their handlers, and at the start of every request declares WordPress's functions with WordPress's signatures, each one line over a `SpeedySpec\WpOptions\Native` function. <Ev source="ss:crates/speedyspec-wp-options-php/src/lib.rs#L1-L10" hash="b8f2b200898210a80a5da12258faf72d294a3e1f5377b97d3c31c267d1a54906"/> <Ev source="ss:crates/speedyspec-wp-options-php/src/lib.rs#L174-L179" hash="aeb597780d83ab81e4da2e7fcee47366a0c78d9fcc9c86daa87dc275ecb9da4d"/>
- **`speedyspec-wp-options-tests`** holds the integration tests of the API on the memory repository. <Ev source="ss:crates/speedyspec-wp-options-tests/src/lib.rs#L1-L3" hash="0655c5b8609e33994e2145705dd77153b2818d5d309cc41986361ef22e776cb6"/>
- **`speedyspec-php-serialize`** is PHP's serialize format in Rust, with WordPress's `maybe_serialize()` family; no PHP runs. <Ev source="ss:crates/speedyspec-php-serialize/src/lib.rs#L1-L2" hash="5f019b64cd67b899243acda81a4b735ef43e3d78bb1e7427a9eafda493e4bb93"/> <Ev test="speedyspec-php-serialize::maybe::maybe_serialize_rules"/> <Ev test="speedyspec-php-serialize::format::round_trip"/>

## Ports

- **`OptionRepository`**: `wp_options` by name, one method per `$wpdb` call `option.php` makes, so query counts match. `SitemetaRepository` is the same for `wp_sitemeta`. Both repositories pass the shared conformance suite. <Ev source="ss:crates/speedyspec-wp-options/src/ports.rs#L1-L11" hash="34e559f205a4acb8508367c83fc7c16ea0b1ac48e00ee10e55ba36f731e44621"/> <Ev source="ss:crates/speedyspec-wp-options/src/sitemeta.rs#L23-L24" hash="1233e6236d0b1af5944f7b891a2c0a1ab001899cc35ebe214a5066263faf5865"/> <Ev test="speedyspec-wp-options-memory::conformance::memory_conformance"/> <Ev test="speedyspec-wp-options-sql::mysql::mysql_conformance"/>
- **What WordPress still answers**: `ValueCodec` (`maybe_serialize()`, `maybe_unserialize()`, object copies), `Installing`, `Multisite`, `Sanitizing` (`sanitize_option()`), `Deprecations`, `ProtectedOptions` (`wp_die()`) and `OptionGroups` (`$new_allowed_options`). Each has a Rust adapter and a PHP one that calls WordPress's function when it exists. <Ev source="ss:crates/speedyspec-wp-options/src/ports.rs#L74-L134" hash="7bdd93ec6d0b59671cdcf40fec609294ac479bc30549bc44c16c34b68ede111a"/> <Ev source="ss:crates/speedyspec-wp-options-php/src/adapters.rs#L94-L119" hash="494eba9aeb8307ac7f8270699595505be4f0574152ffdca9245f5fdc0d936cc3"/>
- **`AutoloadPolicy`** decides an option's `autoload` value and which values autoload (Strategy); `WordPressAutoloadPolicy` is WordPress's, with its two filters. <Ev source="ss:crates/speedyspec-wp-options/src/autoload_policy.rs#L10-L27" hash="61687ecfcffea00027ec8bfcdc0674da73772934bd5a2c4cc8e2640a15986ee8"/>
- **Transients and settings** add `ExternalObjectCache` (`wp_using_ext_object_cache()`), `Clock`, `ExpiredTransients`, `SettingsStore` and `ArgsParsing`. In PHP, `PhpSettingsStore` keeps the registry in `$wp_registered_settings` and `$new_allowed_options`. <Ev source="ss:crates/speedyspec-wp-options/src/transients.rs#L40-L52" hash="bc81a408d20e048ebe7dfc70b03ef8066294a14e044cf0f9ca0c37a9e0ab18ff"/> <Ev source="ss:crates/speedyspec-wp-options/src/settings.rs#L15-L24" hash="3dff9c3b7f25a37b8b8d4e40ef49585b4c334f4e14ae864dc764af9b70c22b56"/>

`OptionsDeps` gathers them; the object cache is the request's current Rust cache, and the hooks are the native Hook API. <Ev source="ss:crates/speedyspec-wp-options/src/api.rs#L15-L30" hash="bbf1a6c2eb354a48902e571143cf689a817ee11c20add8f40588a10c714b41e9"/>

## Use cases

Every function is a command or a query on the buses. Queries: `GetOption`, `GetOptions`, `LoadAlloptions`, `DetermineOptionAutoloadValue`, `FilterDefaultAutoloadValueViaOptionSize`, `AutoloadValuesToAutoload`, `GetNetworkOption`, `GetTransient`, `GetSiteTransient`, `GetRegisteredSettings` and `FilterDefaultOption`. Commands: `AddOption`, `UpdateOption`, `DeleteOption`, `PrimeOptionCaches`, `PrimeOptionCachesByGroup`, `SetOptionAutoloadValues`, `SetOptionsAutoload`, `SetOptionAutoload`, `ProtectSpecialOption`, `AddNetworkOption`, `UpdateNetworkOption`, `DeleteNetworkOption`, `PrimeNetworkOptionCaches`, `LoadCoreSiteOptions`, `SetTransient`, `DeleteTransient`, `SetSiteTransient`, `DeleteSiteTransient`, `DeleteExpiredTransients`, `RegisterSetting` and `UnregisterSetting`. The `*_site_option` functions send the network messages for the current network. <Ev source="ss:crates/speedyspec-wp-options/src/messages.rs#L56-L82" hash="b842952ee76a8579165a1cf412a8e0cd3eed7c99ce080c136b3064f6e3be68d9"/> <Ev source="ss:crates/speedyspec-wp-options/src/network_messages.rs#L1-L2" hash="70b624ed052524bfceda26cefe03c952eca723497f57c41f21a48ecb2777f612"/>

Each handler is bound in the container under `SpeedySpec\WpOptions\<Message>Handler`, for example `SpeedySpec\WpOptions\GetOptionHandler`. A native function resolves its handler once, and again only when that binding changes. <Ev source="ss:crates/speedyspec-wp-options/src/messages.rs#L25" hash="615b69850d2a57c6744ad6952289ad4702b6b49e1404d47264a7de7091d5b817"/> <Ev source="ss:crates/speedyspec-wp-options/src/messages.rs#L91-L98" hash="5bccc1c5dc382b639ff079c7c0eadd829447b2f7a8aaadf50fb5b6a4f3420f74"/> <Ev test="speedyspec-wp-options-tests::messages::handlers_are_bound"/>

Rust code also gets three things PHP doesn't: `Options`, a typed reader (`get::<String>("blogname")`); `update_option_if_unchanged()`, a compare-and-swap write that cron uses for its `cron` option; and `Staged`, option writes through a unit of work, whose actions fire only after the commit. <Ev source="ss:crates/speedyspec-wp-options/src/facade.rs#L47-L66" hash="69f7bda5872a6ac444eef75a3d0cca050d7fba98908354b6996fd1040fd037d2"/> <Ev source="ss:crates/speedyspec-wp-options/src/conditional.rs#L1-L2" hash="32f0e8dd908551c2e7c740ff1e5f690bf4a30bc41ec99ca7c86d189fbcfbe315"/> <Ev source="ss:crates/speedyspec-wp-options/src/staged.rs#L1-L2" hash="6e81794af3ae2a54f8e6022b36d6bdb1699a870af2b204edf59188a482b7222f"/> <Ev test="speedyspec-wp-options-tests::conditional::matching_bytes_write_and_fire_hooks"/> <Ev test="speedyspec-wp-options-tests::staged::filters_at_registration_actions_after_commit"/>

## How to change this

- **Store options elsewhere:** implement `OptionRepository` (and `SitemetaRepository` for networks) and keep the conformance suite passing; `OptionsArea` builds the API on `SqlOptionRepository` today. <Ev source="ss:crates/speedyspec-wp-options-php/src/lib.rs#L105-L118" hash="adde192d07c6006b6aa142a815eea2598f6680ec3233a42730d10bf34cbc54f3"/>
- **Replace one use case from Rust:** bind another handler under its key; the native functions and the buses then call it.
- **From PHP:** options are not replaceable yet. The worker declares PHP ports only for the hook store and a few other areas, so a PHP object bound under an options key isn't used. Hook the options filters instead, as in WordPress. <Ev source="ss:crates/speedyspec-php-runtime/src/worker.rs#L305-L311" hash="7fbab70c0a2dd82e41c3c88572705a9db3e7d738e819ea1925482d7a427d3d03"/>
- **What must still pass:** the recorded scenarios (`compat/options/scenarios.json`, single site and multisite) and WordPress's option tests. A test the port can't match is marked `@group documented-break` and listed in `compat/options/breaks.json`; none is. <Ev test="speedyspec-wp-options-php::wordpress::documented_breaks_are_listed"/>
- **Recording a new scenario:** add it to `compat/options/scenarios.json` in speedyspec-server and record it on MySQL against the pinned release, WordPress 7.2-RC2 (`compat/wordpress.json`).

## Patterns

- **Ports and Adapters** for storage (`OptionRepository`, `SitemetaRepository`) and for what WordPress still answers, each with a Rust and a PHP adapter.
- **Repository** and **Data Mapper**: `SqlOptionRepository` and `OptionMapper` map rows to the plain `Option` entity, which never stores itself.
- **Serialized LOB**: `SerializedValue`, the value as the column holds it.
- **Strategy** for `AutoloadPolicy`, `ValueCodec` and `ArgsParsing`.
- **Command and query handlers** for each function, bound in the container (**Registry**); `SettingsRegistry` is a Registry too.
- **Optimistic Offline Lock** for `update_option_if_unchanged()`, and **Unit of Work** for `Staged`.
- **Facade**: the PHP functions over the native ones, and `Options` for typed reads in Rust.

## A runtime feature calling the API

A Rust feature reads an option through the query bus, so it gets the same value PHP would, filters included. A value PHP wrote is visible to it. <Ev source="ss:crates/speedyspec-wp-options-php/tests/php.rs#L191-L202" hash="bd4de1e015ae2b62c88b03f3b890e2bd6f3d178141ed710d613a39591aa65315"/>

```rust
use std::rc::Rc;

use speedyspec_container::Container;
use speedyspec_cqrs::QueryBus;
use speedyspec_wp_hooks::HookValue;
use speedyspec_wp_options::GetOption;

fn site_title(container: Rc<Container>) -> Result<String, Box<dyn std::error::Error>> {
    let value = QueryBus::new(container)
        .ask(GetOption { name: "blogname".into(), default: Some(HookValue::Str(String::new())) })??;
    Ok(match value.read().as_ref() {
        HookValue::Str(title) => title.clone(),
        _ => String::new(),
    })
}
```
