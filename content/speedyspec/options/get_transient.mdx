## Behaviour

Native: the `GetTransient` query. Reading an expired transient deletes it, as in WordPress; with a persistent object cache the value comes from the cache instead. <Ev scenario="transient_basics" area="options"/> <Ev scenario="transient_expired_read_deletes" area="options"/> <Ev scenario="transient_ext_object_cache" area="options"/> <Ev scenario="transient_filters_change_values" area="options"/> <Ev test="speedyspec-wp-options-php::wordpress::wordpress_option_runs_pass"/>

## Override

Transients go through the options API, or the object cache when it is persistent; the `ExternalObjectCache` and `Clock` ports decide which and when. See the architecture page.
