## theme.json

Not native yet. speedyspec-server has WordPress's theme.json engine in Rust, but the runtime worker doesn't link it: its dependency list names no theme.json crate, and wiring it in would also mean guarding WordPress's class files, which would otherwise declare `WP_Theme_JSON` twice. PHP on SpeedySpec still gets WordPress's own classes. <Ev source="ss:crates/speedyspec-php-runtime/Cargo.toml#L20-L55" hash="955f1ccec24cc11da3fa0826db96868561c6e6c3cdc55277b37b80c09b513508"/> <Ev source="ss:crates/speedyspec-wp-theme-json/README.md#L101-L103" hash="67bfdcd9955266fb5c1444fca27ae3b3eb8ecb89145ed55ca3509428bd7e493d"/>

The port covers four of this seam's five classes: `WP_Theme_JSON`, `WP_Theme_JSON_Schema`, `WP_Theme_JSON_Data` and `WP_Theme_JSON_Resolver`. It declares every public method and constant of each, 40 of their 119 methods; the other 79 are protected or private and have no PHP counterpart in the port (a difference, below). <Ev source="ss:crates/speedyspec-wp-theme-json-php/src/release.rs#L9-L15" hash="f823725f6515b856d7ba4670775cb95e10e7e6fdd2e8492749c76e252778147d"/> The same crate also ports the global styles functions of `global-styles-and-settings.php`, which belong to the Resources seam. <Ev source="ss:crates/speedyspec-wp-theme-json-php/src/release.rs#L17-L30" hash="04374d427a1a9278d9235d385b65a48b26c33568466a452b1e3bc8dade9690cc"/>

How it is checked:

- **Recorded scenarios.** `compat/theme-json` holds 424 scenarios recorded from WordPress 7.1.5: the class constants, schema migration, merging, the data methods, stylesheets by type for core's `theme.json` and Twenty Twenty-Three to Twenty-Five, selectors, insecure-property removal, SVG filters, `wp_filter_global_styles_post`, the resolver over WordPress's test themes, and the global styles functions. `speedyspec-wp-theme-json-php`'s `compat` test replays them through the native classes. No break is recorded. <Ev area="theme-json" scenario="constant_ROOT_BLOCK_SELECTOR"/> <Ev area="theme-json" scenario="schema_migrate_v1"/> <Ev area="theme-json" scenario="merge_default_slugs_removed_from_theme_presets"/> <Ev area="theme-json" scenario="stylesheet_stylesheet_default_types"/> <Ev area="theme-json" scenario="security_removes_unsafe_styles"/> <Ev area="theme-json" scenario="resolver_get_core_data"/> <Ev area="theme-json" scenario="global_styles_global_settings_block_theme"/> <Ev source="ss:compat/theme-json/breaks.json#L1" hash="5d53fa22c7f9fa01580c35b299aa3c63412c66884c68ebb3c8cc779e7e9af356"/>
- **WordPress's PHPUnit tests.** WordPress's theme.json tests (`wpThemeJson.php`, `wpThemeJsonSchema.php`, `wpThemeJsonResolver.php`, `wpGetGlobalStylesheet.php`, `wpGetBlockCssSelector.php` and two more) run against the native area, with WordPress's class files emptied. At least 100 must run with no failure. 20 are left out as documented breaks: they reach protected members through Reflection, or compare arrays with `assertSame`, where the port promises equality by `==`. 18 more need a booted WordPress (`needs-wordpress-core`): the database, the posts API, translation files, or the style queue and script loader. <Ev test="speedyspec-wp-theme-json-php::wordpress::wordpress_theme_json_tests_pass"/> <Ev source="ss:crates/speedyspec-wp-theme-json-php/tests/wordpress.rs#L1-L4" hash="1d00c24a116bf1033a7d87e9803df3730ae85e544b4e829f617bea34d2d2fa96"/>
- **The engine's own tests** compare stylesheets, merges, security and the resolver byte for byte with values WordPress 7.1.5 produced. <Ev test="speedyspec-wp-theme-json::stylesheet::stylesheet_default_types"/> <Ev test="speedyspec-wp-theme-json::security::removes_unsafe_styles"/>

The documented differences, none of them recorded as a compat break: arrays are equal to WordPress's by `==`, not `===`; protected members don't exist and overriding one in a subclass changes nothing; a failing `wp_theme_json_get_style_nodes` callback surfaces as an `Error`; duotone filters are always the compact markup; the resolver hands out new objects instead of its statics; and the deprecated `get_custom_css()` reads computed block selectors. <Ev source="ss:crates/speedyspec-wp-theme-json/README.md#L62-L76" hash="21d9498ea8d0660cc10abbad074c7b4d6fb5d558a156523d7e1cc2f39e54b908"/>

The rest of this seam, `WP_Theme` and the template, template-tag, theme-loading and theme-support functions, has no Rust port. It is WordPress's PHP.
