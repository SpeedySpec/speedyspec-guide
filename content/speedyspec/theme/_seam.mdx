## theme.json

Not native yet. speedyspec-server has WordPress's theme.json engine in Rust, but the runtime worker doesn't link it: its dependency list names no theme.json crate, and wiring it in would also mean guarding WordPress's class files, which would otherwise declare `WP_Theme_JSON` twice. PHP on SpeedySpec still gets WordPress's own classes. <Ev source="ss:crates/speedyspec-php-runtime/Cargo.toml#L24-L61" hash="6f4cc0a8bd36744bf5405190b45effa2b6e7bf0dc07102a16609d3f7a8def695"/> <Ev source="ss:crates/speedyspec-wp-theme-json/README.md#L101-L103" hash="67bfdcd9955266fb5c1444fca27ae3b3eb8ecb89145ed55ca3509428bd7e493d"/>

The port covers four of this seam's five classes: `WP_Theme_JSON`, `WP_Theme_JSON_Schema`, `WP_Theme_JSON_Data` and `WP_Theme_JSON_Resolver`. It declares every public method and constant of each, 40 of their 119 methods; the other 79 are protected or private and have no PHP counterpart in the port (a difference, below). <Ev source="ss:crates/speedyspec-wp-theme-json-php/src/release.rs#L9-L15" hash="f823725f6515b856d7ba4670775cb95e10e7e6fdd2e8492749c76e252778147d"/> The same crate also ports the global styles functions of `global-styles-and-settings.php`, which belong to the Resources seam, all but 7.2's new `wp_get_viewport_media_queries()`, which stays WordPress's PHP and calls the native class. <Ev source="ss:crates/speedyspec-wp-theme-json-php/src/release.rs#L17-L31" hash="046b16179178ed35e56be7c467ff60dd3820bf74723ae65da132e04618e3b9fa"/>

The port follows WordPress 7.2-RC2's schema data and behaviour: the resolver caches merged data per origin, split `blockGap` values, text shadows and the `label` element, `background-clip`, text-clip escapes in state styles, kebab-cased preset slugs in `var:preset|…` references, and 7.2's `sanitize()` rules. <Ev area="theme-json" scenario="stylesheet_background_clip_and_text_clip_escapes"/> <Ev area="theme-json" scenario="stylesheet_text_input_pseudo_element_and_label"/> <Ev area="theme-json" scenario="stylesheet_custom_css_feature_selector_and_non_string_css"/>

How it is checked:

- **Recorded scenarios.** `compat/theme-json` holds 427 scenarios recorded from WordPress 7.2-RC2: the class constants, schema migration, merging, the data methods, stylesheets by type for core's `theme.json` and Twenty Twenty-Three to Twenty-Five, selectors, insecure-property removal, SVG filters, `wp_filter_global_styles_post`, the resolver over WordPress's test themes, and the global styles functions. `speedyspec-wp-theme-json-php`'s `compat` test replays them through the native classes. No break is recorded. <Ev area="theme-json" scenario="constant_ROOT_BLOCK_SELECTOR"/> <Ev area="theme-json" scenario="schema_migrate_v1"/> <Ev area="theme-json" scenario="merge_default_slugs_removed_from_theme_presets"/> <Ev area="theme-json" scenario="stylesheet_stylesheet_default_types"/> <Ev area="theme-json" scenario="security_removes_unsafe_styles"/> <Ev area="theme-json" scenario="resolver_get_core_data"/> <Ev area="theme-json" scenario="global_styles_global_settings_block_theme"/> <Ev source="ss:compat/theme-json/breaks.json#L1" hash="5d53fa22c7f9fa01580c35b299aa3c63412c66884c68ebb3c8cc779e7e9af356"/>
- **WordPress's PHPUnit tests.** WordPress's theme.json tests (`wpThemeJson.php`, `wpThemeJsonSchema.php`, `wpThemeJsonResolver.php`, `wpGetGlobalStylesheet.php`, `wpGetBlockCssSelector.php` and two more) run against the native area, with WordPress's class files emptied. `wpThemeJson.php` is copied from WordPress 7.2-RC2, the rest from 7.1.5. At least 100 must run with no failure; 264 run. 25 are left out as documented breaks: they reach protected members through Reflection, or compare arrays with `assertSame`, where the port promises equality by `==`. Five of them are tests 7.2 adds: three call the protected `get_block_selectors()` through Reflection (`test_get_block_selectors_builds_default_selectors_with_root_first`, `test_get_block_selectors_returns_custom_selectors`, `test_get_block_selectors_keeps_root_selector_string`), and two get equal arrays in another key order (`test_sanitize_removes_preset_items_of_unexpected_types`, `test_merge_does_not_generate_spacing_sizes_from_a_non_array_per_origin_spacing_scale`). These are the port's existing deliberate differences, not new ones. 18 more need a booted WordPress (`needs-wordpress-core`): the database, the posts API, translation files, or the style queue and script loader. <Ev test="speedyspec-wp-theme-json-php::wordpress::wordpress_theme_json_tests_pass"/> <Ev source="ss:crates/speedyspec-wp-theme-json-php/tests/wordpress.rs#L1-L4" hash="24288b17d22a0f19299c10d42c66a3ce86572cc0a0b4f3a629a11dcc46e78274"/> <Ev source="ss:crates/speedyspec-wp-theme-json/README.md#L62-L67" hash="2f2140c61d5cc8d222653c8aed235726819157b7900edf36861de978a374e6a3"/>
- **The engine's own tests** compare stylesheets, merges, security and the resolver byte for byte with values WordPress produced, now 7.2-RC2's. The core blocks' `block.json` data the tests use is still 7.1.5's copy, with no generator in the server to refresh it. <Ev test="speedyspec-wp-theme-json::stylesheet::stylesheet_default_types"/> <Ev test="speedyspec-wp-theme-json::security::removes_unsafe_styles"/>

The documented differences, none of them recorded as a compat break: arrays are equal to WordPress's by `==`, not `===`; protected members don't exist and overriding one in a subclass changes nothing; a failing `wp_theme_json_get_style_nodes` callback surfaces as an `Error`; duotone filters are always the compact markup; the resolver hands out new objects instead of its statics; and the deprecated `get_custom_css()` reads computed block selectors. <Ev source="ss:crates/speedyspec-wp-theme-json/README.md#L62-L76" hash="21d9498ea8d0660cc10abbad074c7b4d6fb5d558a156523d7e1cc2f39e54b908"/>

The rest of this seam, `WP_Theme` and the template, template-tag, theme-loading and theme-support functions, has no Rust port. It is WordPress's PHP.
