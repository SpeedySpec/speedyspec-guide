## Behaviour

Native. The global function resolves the `SpeedySpec\WpPassword\PasswordGenerator` port on every call. <Ev source="ss:crates/speedyspec-wp-password-php/src/password.php#L158-L161" hash="76354fcefc52b6dda40ffb0ccc4c63ad6d90518bd7a2d872bc8c9a3bcd41c2ae"/> It draws each character through the bound `RandomNumber` port, the one `wp_rand()` uses, as WordPress draws through `wp_rand()`. <Ev test="speedyspec-wp-password::random::generate_uses_bound_random_number"/> <Ev test="speedyspec-wp-password-php::php::generator_draws_through_bound_random_number"/> The password lengths WordPress 7.2-RC2 gave for recorded `$length` values, odd types included, are replayed. <Ev test="speedyspec-wp-password::random::generate_length_replayed"/> <Ev test="speedyspec-wp-password-php::php::rand_and_generate_follow_wordpress"/> The signature matches WordPress's. <Ev test="speedyspec-wp-password-php::php::signatures_match_wordpress"/>

WordPress's own tests don't call `wp_generate_password()` directly, so the proof is the recorded cases and the server's tests above.

## Replacing it

Bind your own class under `SpeedySpec\WpPassword\PasswordGenerator` for the request, where WordPress would have a plugin declare `wp_generate_password()` first. See the [Passwords and crypto architecture](/speedyspec/architecture/password/) page.
