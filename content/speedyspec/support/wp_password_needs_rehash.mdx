## Behaviour

Native. The global function resolves the `SpeedySpec\WpPassword\RehashPolicy` port on every call. <Ev source="ss:crates/speedyspec-wp-password-php/src/password.php#L138-L141" hash="27bbbdfd7d99ee7009a9ecf910cb16997d304d3d5663159072eb64da4d2bf39e"/> It replays WordPress 7.1.5's recorded answers. <Ev test="speedyspec-wp-password::rehash::rehash_replays_recorded"/> The `password_needs_rehash` filter gets the hash and the user ID, and a set `$wp_hasher` means no rehash and no filters, as in WordPress. <Ev test="speedyspec-wp-password::rehash::filter_receives_hash_and_user_id"/> <Ev test="speedyspec-wp-password::rehash::wp_hasher_set_means_no_rehash_and_no_filters"/> WordPress's `authPassword.php` tests pass against it, except the bcrypt-cost test listed as an expected failure. <Ev test="speedyspec-wp-password-php::wordpress::wordpress_password_tests_pass_but_divergences"/>

## Differences

argon2id is the default algorithm, so a bcrypt hash (`$wp$2y$`, or a plain `$2y$`) needs a rehash, and the user's next login rewrites it as argon2id. WordPress, whose default is bcrypt, keeps it. <Ev test="speedyspec-wp-password::rehash::bcrypt_needs_rehash_under_argon2id_default"/> <Ev source="ss:crates/speedyspec-wp-password-php/tests/wordpress.rs#L19-L30" hash="bd25750da7897a1d9172599f83d9d1fda688ca4a230302c7e31a313d14c50e98"/>

## Replacing it

Bind your own class under `SpeedySpec\WpPassword\RehashPolicy` for the request. See the [Passwords and crypto architecture](/speedyspec/architecture/password/) page.
