Not linked yet: speedyspec-server has ported part of this seam to Rust, but the runtime worker doesn't link those crates, so PHP on SpeedySpec still gets WordPress's own translation, UTF-8 and token map code. <Ev source="ss:crates/speedyspec-php-runtime/Cargo.toml#L18-L62" hash="c9624e3847b039aeed6abb31f7fe4d3d2be1d1ced2cd37ab00ef885f1b91a07f"/> What follows is what the port covers, and its evidence, for when it is linked.

## What the port covers

Of the seam's 86 functions, the port declares 23 natively:

- **9 from `l10n.php`:** `translate()`, `translate_with_gettext_context()`, `__()`, `_x()`, `_n()`, `_nx()`, `_load_script_textdomain_from_src()`, `load_script_translations()` and `translate_settings_using_i18n_schema()`. <Ev source="ss:crates/speedyspec-wp-i18n-php/src/release.rs#L9-L20" hash="a871221d490697b39a8d62ab93d38df153adb461133359d172148c4975881e1b"/> The six gettext functions serve the common call themselves, a loaded domain with nothing hooked to its filters, and give every other call to WordPress's own function, so the result is WordPress's in every case. <Ev test="speedyspec-wp-i18n-php::php::plain_calls_take_the_fast_path"/> <Ev test="speedyspec-wp-i18n-php::php::empty_context_runs_the_context_filters"/>
- **14 UTF-8 functions:** every function of `utf8.php` and `compat-utf8.php`, and `compat.php`'s `_is_utf8_charset()`, `_mb_substr()` and `_mb_strlen()`, each a thin PHP function with WordPress's signature over a native one. <Ev source="ss:crates/speedyspec-wp-utf8-php/src/lib.rs#L1-L6" hash="dd023bef57d6132a64f5feeb7c67f738079b063aed5bb4e7fd33cec48e767802"/> <Ev test="speedyspec-wp-utf8-php::php::natives_are_registered_and_match"/>

Classes: `WP_Translation_Controller` and the `WP_Translation_File` classes are shells over the Rust controller; `WP_Locale`, `WP_Locale_Switcher` and `Plural_Forms` are native; `MO` and `PO` keep WordPress's code with native fast paths taken only when the methods they stand for aren't overridden; `WP_Token_Map` answers WordPress's HTML5 named character reference table natively and runs WordPress's code for other maps. <Ev test="speedyspec-wp-i18n-php::php::wp_locale_is_native"/> <Ev test="speedyspec-wp-i18n-php::php::switcher_is_native"/> <Ev test="speedyspec-wp-i18n-php::php::plural_forms_is_native"/> <Ev test="speedyspec-wp-i18n-php::php::mo_is_native"/> <Ev test="speedyspec-wp-token-map-php::php::html5_table_reads_natively"/> <Ev test="speedyspec-wp-token-map-php::php::other_maps_run_wordpress_code"/>

## The evidence

- **WordPress's own tests:** the l10n and POMO tests (15 files under `tests/php/wordpress/l10n`), the UTF-8 tests (`unicode` and three `compat` files) and `Tests_WpTokenMap`, copied from WordPress 7.1.5, pass against the native areas under the pinned PHPUnit. Each run checks the suite's own totals (at least 30, 100 and 2,000 tests) and no failures or errors. <Ev test="speedyspec-wp-i18n-php::wordpress::wordpress_i18n_tests_pass"/> <Ev test="speedyspec-wp-utf8-php::wordpress::wordpress_utf8_tests_pass"/> <Ev test="speedyspec-wp-token-map-php::wordpress::wordpress_token_map_tests_pass"/>
- **Documented breaks:** none. The three areas' `breaks.json` list no WordPress test, and each run fails if a test is excluded without being listed. <Ev source="ss:compat/i18n/breaks.json#L1-L3" hash="b20fe731f42f98b7a666dd824bf7da02b5c61093fc4b00e0de285465f5040b7f"/> <Ev source="ss:compat/utf8/breaks.json#L1-L3" hash="b20fe731f42f98b7a666dd824bf7da02b5c61093fc4b00e0de285465f5040b7f"/> <Ev source="ss:compat/token-map/breaks.json#L1-L3" hash="cfca7c434acf078259cd2b79a4b486a4fbc959bacecba74c47f4b27ac18ab043"/> <Ev test="speedyspec-wp-i18n-php::wordpress::documented_breaks_are_listed"/>
- **Recorded cases:** calls recorded from stock WordPress (`compat/i18n`, `compat/utf8`, `compat/token-map`, as `cases.json` rather than scenarios) replay with the same results. <Ev test="speedyspec-wp-i18n-php::php::recorded_calls_replay"/> <Ev test="speedyspec-wp-utf8-php::php::recorded_cases_replay"/> <Ev test="speedyspec-wp-token-map-php::php::recorded_calls_replay"/>

## Still WordPress's PHP

Even once linked, the port leaves 63 functions to WordPress: the rest of `l10n.php` (loading text domains, `determine_locale()`, `get_locale()`, the `esc_*__()` wrappers and the functions that only forward to `$wp_locale`, `$wp_locale_switcher` or `wp_scripts()`) and `compat.php`'s polyfills other than the three UTF-8 helpers. `WP_Textdomain_Registry`, `Translations`, `Gettext_Translations`, `NOOP_Translations`, `Translation_Entry` and the `POMO_*Reader` streams also stay WordPress's PHP. <Ev source="ss:crates/speedyspec-wp-i18n-php/src/lib.rs#L13-L24" hash="8017cdfadd86abcebb2a86ece4b65ccb38b117ab233e59c463d08e842b9b201a"/>
