## The crates

Passwords:

- **`speedyspec-wp-password-contracts`**: the ports, one per pluggable function, and what WordPress's own implementations reach outside themselves. Its only dependency is the Hook API's `Value`. <Ev source="ss:crates/speedyspec-wp-password-contracts/src/lib.rs#L1-L21" hash="69532283911e5cb04c1e603961f2a66234e8d4408e7ab9ab3b43d5a9f10773a7"/>
- **`speedyspec-wp-password`**: WordPress's password rules in Rust, independent of the cryptography and of PHP. <Ev source="ss:crates/speedyspec-wp-password/src/lib.rs#L1-L16" hash="c8d00ccec261f253817dfc0b252b6597d93ddf36006ed6de81aeec1acdd86e8e"/>
- **`speedyspec-wp-password-bcrypt`**: the `Bcrypt` port over the `bcrypt` crate, matching PHP's `crypt()` and `password_verify()` byte for byte (a password stops at its first NUL byte, as crypt_blowfish reads it). <Ev test="speedyspec-wp-password-bcrypt::vectors::hash_matches_php_crypt"/> <Ev test="speedyspec-wp-password-bcrypt::vectors::verifies_php_vectors_all_variants"/>
- **`speedyspec-wp-password-php`**: the PHP area. It binds the defaults, registers the ports PHP may replace, and declares the global functions. <Ev source="ss:crates/speedyspec-wp-password-php/src/lib.rs#L1-L20" hash="09cceaffba8a6828ae889e8ca2acdee9e8e8a4e7d0c4eaaed7933b0cc00c0eaa"/>

Crypto:

- **`speedyspec-wp-crypto-contracts`**: the crypto ports (keyed BLAKE2b, Ed25519, base64, the library version, the clock, the file hash, translation, the `wp_trusted_keys` filter, raw argon2, random bytes). <Ev source="ss:crates/speedyspec-wp-crypto-contracts/src/lib.rs#L1-L19" hash="cd302d47d5bed67f3e0dc2cccde7a4fc8054ed5b00c8405081b7e45e13cf68d5"/>
- **`speedyspec-wp-crypto`**: WordPress's rules for those functions: the `$generic$` format, the trusted keys, the signature loop and its messages. <Ev source="ss:crates/speedyspec-wp-crypto/src/lib.rs#L1-L9" hash="73fd61764aa71b8acbf38df119ba537e8edb04d49507d5c26875857a537d9801"/>
- **`speedyspec-wp-crypto-sodium`**: the crypto ports over libsodium, called from Rust, linking the same `libsodium.a` as the static PHP's ext-sodium. <Ev source="ss:crates/speedyspec-wp-crypto-sodium/src/lib.rs#L1-L5" hash="ec57c46033ed3e9ce17d7639bc6b6f128a073a504aa07bc58508e0d8a4b0554b"/> <Ev test="speedyspec-wp-crypto-sodium::vectors::version_is_pinned"/> <Ev test="speedyspec-wp-crypto-sodium::password_vectors::argon2_matches_php_sodium_crypto_pwhash"/>
- **`speedyspec-wp-crypto-php`**: the PHP area for the four sodium functions. <Ev source="ss:crates/speedyspec-wp-crypto-php/src/lib.rs#L1-L14" hash="28150493bcb46537807125e460b50267f836a11bc5da3476885155008c2306c2"/>

## The contracts

Each pluggable function is one port, so each can be replaced alone, as in WordPress. The container key is also the name of the PHP twin interface. <Ev source="ss:crates/speedyspec-wp-password-contracts/src/lib.rs#L26-L37" hash="4bb8935855b3e6e9200a1c3c02845cfb9ad4faba77b41734b3518c567a72fc75"/>

| Port | WordPress | Container key |
|---|---|---|
| `PasswordHasher::hash` | `wp_hash_password()` | `SpeedySpec\WpPassword\PasswordHasher` |
| `PasswordChecker::check` | `wp_check_password()` | `SpeedySpec\WpPassword\PasswordChecker` |
| `RehashPolicy::needs_rehash` | `wp_password_needs_rehash()` | `SpeedySpec\WpPassword\RehashPolicy` |
| `PasswordGenerator::generate` | `wp_generate_password()` | `SpeedySpec\WpPassword\PasswordGenerator` |
| `RandomNumber::rand` | `wp_rand()` | `SpeedySpec\WpPassword\RandomNumber` |
| `PasswordCostLimits::limits` | none: the site's ceiling on hashing costs | `SpeedySpec\WpPassword\PasswordCostLimits` |

The outbound ports the rules use: `PasswordFilters` (the five filters, through the Hook API), `WpHasherGlobal` (a plugin's `$wp_hasher`), `Bcrypt`, `Warnings`, and the crypto contracts' `Argon2` and `RandomBytes`. `PasswordPorts` gathers them. <Ev source="ss:crates/speedyspec-wp-password-contracts/src/lib.rs#L121-L185" hash="e9d378c23677290815428c34bec2f6bf308788bfb712750ac9b2df8cfd2c4a79"/>

Values are the Hook API's `Value`, because WordPress returns whatever its filters return. Passwords and hashes are bytes, as PHP strings are.

## The use cases

Each port's default is one use case, a command or query over the outbound ports:

- **Hash a password** (`DefaultPasswordHasher`): a Strategy per algorithm (WordPress's `$wp` bcrypt, plain bcrypt, argon2), chosen by the filtered algorithm.
- **Check a password** (`DefaultPasswordChecker`): a Chain of Responsibility over hash formats, in WordPress's `if`/`elseif` order. <Ev source="ss:crates/speedyspec-wp-password/src/check.rs#L200-L220" hash="b088accfafbb991404e582ed288c4843c1cd7207eadac319153086f5679bf251"/>
- **Decide on a rehash** (`DefaultRehashPolicy`), **draw a random number** (`DefaultRandomNumber`) and **generate a password** (`DefaultPasswordGenerator`, which draws through whatever `wp_rand()` is bound). <Ev test="speedyspec-wp-password-php::php::generator_draws_through_bound_random_number"/>
- **Application passwords**: `application_password_hash()`, `application_password_check()` and `chunk_password()`, `WP_Application_Passwords`' three rules. A `$generic$` hash is a fast hash; any other goes to the bound checker. <Ev test="speedyspec-wp-password::application::application_check_other_uses_bound_checker"/>
- **Fast hash, trusted keys, file signatures**: `wp_fast_hash()`, `wp_verify_fast_hash()`, `default_trusted_keys()` and `check_signatures()` in `speedyspec-wp-crypto`, pure functions over the crypto ports. <Ev test="speedyspec-wp-crypto::core::loop_first_match_wins"/>

## The adapters and the container keys

- **Defaults.** `PasswordArea::bind_defaults()` binds WordPress's rules under the five ports, over libsodium (argon2, random bytes) and the bcrypt crate, and `CostLimits::DEFAULT` under the limits' port, for the worker's life. <Ev source="ss:crates/speedyspec-wp-password-php/src/lib.rs#L78-L123" hash="fe396bf5f290f4f2abe76525941883d4e062e09c2544b31e7a65b3c7a341101d"/> <Ev test="speedyspec-wp-password-php::bindings::default_cost_limits_are_bound"/>
- **PHP replacements.** `PasswordArea::ports()` registers the six ports, so a PHP object bound under one reaches Rust callers as a `PhpReplacement`. <Ev source="ss:crates/speedyspec-wp-password-php/src/lib.rs#L127-L142" hash="ce1d9de80df2eead6083474e8cc3bedd3b95d4f0bf28eda5f21709459a2468bb"/> The twin interfaces are generated by `#[php_port]`. <Ev source="ss:crates/speedyspec-wp-password-php/src/twins.rs#L10-L45" hash="9e4a06848d3bc82a6da9e221106396c2b3f0749606ca80a3d0bc0c138d3578ee"/>
- **Hook API and PHP.** `HookPasswordFilters` runs the filters; `PhpWpHasherGlobal` reads `$wp_hasher`; `PhpWarnings` raises PHP warnings; `ResolvedCostLimits` resolves the limits' port per call. <Ev source="ss:crates/speedyspec-wp-password-php/src/lib.rs#L45-L47" hash="0d5c97e2b600ba8ade183b4e24f8f8d1457b19c747e4bddda957be1fdc1173fa"/>
- **The facades.** `password.php` declares the global functions at the start of every request, each in a `function_exists` guard, and each resolves its port per call. `crypto.php` does the same for the sodium functions, which call libsodium directly, never PHP's `sodium_*` functions. <Ev source="ss:crates/speedyspec-wp-password-php/src/natives.rs#L84-L89" hash="5a0c5351169eb6bf29d326cc578f97d2b38b100a85d2693db58df5827406a784"/> <Ev source="ss:crates/speedyspec-wp-crypto-php/src/lib.rs#L3-L11" hash="15be0d9b11dfbb43855465730b48a38c8c7842503a1ed8f64a1dd693ab0a5551"/>
- **The crypto area has no container key.** `CryptoArea::new()` takes libsodium (`Sodium`) itself, and the worker initializes it once for both areas. <Ev source="ss:crates/speedyspec-wp-crypto-php/src/lib.rs#L40-L48" hash="08de5a2196b5f165e3c4f457bf66823dc86a767061ed83f3cb808e1d0e3d66ec"/>

## Patterns

- **Ports and Adapters**: one port per pluggable function; libsodium, bcrypt, the Hook API and PHP sit behind adapters.
- **Strategy** for the hash algorithm; **Chain of Responsibility** for the hash formats a check recognises.
- **Special Case** for `$wp_hasher`: an empty global is "no hasher", so the rules need not know about PHP.
- **Registry** (the container) in place of pluggable functions; **Plugin** for PHP's replacements, wrapped by an **Adapter** (`PhpReplacement`) so Rust callers see the port.
- **Facade**: `password.php` and `crypto.php` over the natives.

## How to change this

- **Replace one function from PHP:** implement its twin interface in a class and bind the class name, for one request, or for every request in `app.<id>.php.bindings`. Bind a class name, not a closure:

  ```php
  \SpeedySpec\Container\Container::getInstance()->bind(
      \SpeedySpec\WpPassword\PasswordHasher::class,
      My_Plugin_Password_Hasher::class
  );
  ```

  A replacement's exception reaches the caller unchanged, and the binding ends with the request. <Ev test="speedyspec-wp-password-php::php::throwing_override_surfaces_as_php_exception"/> <Ev test="speedyspec-wp-password-php::php::override_ends_with_the_request"/>
- **Set the site's cost limits:** bind `SpeedySpec\WpPassword\PasswordCostLimits`; `limits()` returns any of `cost`, `memory_cost` and `time_cost`. <Ev test="speedyspec-wp-password-php::php::php_bound_cost_limits_cap_hashing_and_checking"/>
- **Replace one from Rust:** bind your own implementation with `bind_port` under the same key. <Ev test="speedyspec-wp-password-php::bindings::a_site_binding_its_cost_limits_caps_the_default_hasher"/>
- **Other crypto:** implement the crypto contracts' ports and call `speedyspec-wp-crypto`'s rules with them; the PHP area itself is built over libsodium.
- **What must still pass:** WordPress's password and sodium tests (except the listed failures) and the recorded cases. <Ev test="speedyspec-wp-password-php::wordpress::wordpress_password_tests_pass_but_divergences"/> <Ev test="speedyspec-wp-crypto-php::wordpress::wordpress_crypto_tests_pass_but_phpass"/>

## Calling it from Rust

A runtime feature that checks a password resolves the port, so a PHP replacement answers it too:

```rust
use speedyspec_container::Container;
use speedyspec_wp_password_contracts::{PASSWORD_CHECKER, PasswordChecker, Value};

/// Whether `password` matches the stored `hash`, as `wp_check_password()` answers.
fn password_matches(container: &Container, password: &[u8], hash: &[u8], user_id: i64) -> bool {
    let Ok(checker) = container.make_port::<dyn PasswordChecker>(PASSWORD_CHECKER) else {
        return false;
    };
    matches!(checker.check(password, hash, &Value::Int(user_id)), Ok(Value::Bool(true)))
}
```
