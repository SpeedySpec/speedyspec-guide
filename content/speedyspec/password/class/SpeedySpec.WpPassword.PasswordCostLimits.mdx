## Behaviour

The site's ceiling on password hashing costs; WordPress has no counterpart. PHP's `password_verify()` runs whatever cost a stored hash names, so one planted hash can hold a worker for hours. On SpeedySpec a stored hash above a limit never verifies (its user resets their password), and `wp_hash_password()` refuses options above them with PHP's `ValueError`, so a site never writes a hash it can't verify. <Ev source="ss:crates/speedyspec-wp-password-contracts/src/lib.rs#L187-L212" hash="c19e776f555047f2203acd57a7e5e55a9bd7b4ae958e29ca008412ff1ef526db"/> <Ev test="speedyspec-wp-password::check::bcrypt_above_the_cost_limit_never_verifies_nor_runs"/> <Ev test="speedyspec-wp-password::check::argon2_above_the_cost_limits_never_verifies_nor_runs"/>

Its one method, `limits()`, returns an array with any of `cost` (bcrypt), `memory_cost` (argon2, in KiB) and `time_cost` (argon2), as `password_hash()` names its options; a missing key keeps its default. The defaults are bcrypt cost 16, argon2 256 MiB and 10 passes. <Ev source="ss:crates/speedyspec-wp-password-php/src/twins.rs#L40-L45" hash="03e50ff99f617eeb3cc973d99ac692ca951b85f078bda2898c9e9f966446cdb2"/> <Ev test="speedyspec-wp-password::hash::default_cost_limits_are_bcrypt_16_and_argon2_256_mib_10_passes"/>

## Override

Bind a class implementing this interface under `SpeedySpec\WpPassword\PasswordCostLimits`, for one request or in `app.<id>.php.bindings`. A value outside what PHP accepts (a bcrypt `cost` above 31, say) is a `ValueError` naming this method. <Ev test="speedyspec-wp-password-php::php::php_bound_cost_limits_cap_hashing_and_checking"/>
