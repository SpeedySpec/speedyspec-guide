## Behaviour

The PHP twin of the `PasswordGenerator` port, which answers `wp_generate_password()`. Its one method, `generate( $length, $special, $extra )`, returns a random password; the arguments are PHP values, as WordPress passes them on. `#[php_port]` declares it at the start of every request from the Rust trait, so the two can't drift. <Ev source="ss:crates/speedyspec-wp-password-php/src/twins.rs#L28-L32" hash="a17b44ed98d499ab4b493c9fb93e5c15911deef07f304cbb1005775e5dce241b"/>

## Override

Where WordPress lets a plugin declare `wp_generate_password()` first, bind a class implementing this interface under `SpeedySpec\WpPassword\PasswordGenerator`. It then answers `wp_generate_password()` for PHP and for Rust callers, until the request ends. <Ev test="speedyspec-wp-password-php::php::php_override_replaces_default"/> <Ev test="speedyspec-wp-password-php::php::rust_callers_get_the_php_override"/> <Ev test="speedyspec-wp-password-php::php::override_ends_with_the_request"/> An exception your method throws reaches the caller unchanged. <Ev test="speedyspec-wp-password-php::php::throwing_override_surfaces_as_php_exception"/> See the architecture page.
