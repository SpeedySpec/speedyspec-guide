## Behaviour

The PHP twin of the `RandomNumber` port, which answers `wp_rand()`. Its one method, `rand( $min, $max )`, returns a random number between `$min` and `$max`, in either order, after `wp_rand()`'s defaults and `(int)` casts. `#[php_port]` declares it at the start of every request from the Rust trait, so the two can't drift. <Ev source="ss:crates/speedyspec-wp-password-php/src/twins.rs#L34-L38" hash="91d588b5adb7cbecc05baa69fbf61fbc133c5ecddb5779e6263ba0c60e3d6fb7"/>

## Override

Where WordPress lets a plugin declare `wp_rand()` first, bind a class implementing this interface under `SpeedySpec\WpPassword\RandomNumber`. It then answers `wp_rand()` for PHP and for Rust callers, until the request ends. <Ev test="speedyspec-wp-password-php::php::php_override_replaces_default"/> <Ev test="speedyspec-wp-password-php::php::rust_callers_get_the_php_override"/> <Ev test="speedyspec-wp-password-php::php::override_ends_with_the_request"/> An exception your method throws reaches the caller unchanged. <Ev test="speedyspec-wp-password-php::php::throwing_override_surfaces_as_php_exception"/> See the architecture page.

The default `wp_generate_password()` draws its characters through whatever is bound here. <Ev test="speedyspec-wp-password-php::php::generator_draws_through_bound_random_number"/>
