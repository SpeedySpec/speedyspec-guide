## Behaviour

The PHP twin of the `RehashPolicy` port, which answers `wp_password_needs_rehash()`. Its one method, `needs_rehash( $hash, $user_id )`, answers whether the hash should be replaced by a fresh one. `#[php_port]` declares it at the start of every request from the Rust trait, so the two can't drift. <Ev source="ss:crates/speedyspec-wp-password-php/src/twins.rs#L22-L26" hash="dac02c10a6c4f1dfcb5666b9e83ae029cdda3b333cf0e05f12238a35d5fac193"/>

## Override

Where WordPress lets a plugin declare `wp_password_needs_rehash()` first, bind a class implementing this interface under `SpeedySpec\WpPassword\RehashPolicy`. It then answers `wp_password_needs_rehash()` for PHP and for Rust callers, until the request ends. <Ev test="speedyspec-wp-password-php::php::php_override_replaces_default"/> <Ev test="speedyspec-wp-password-php::php::rust_callers_get_the_php_override"/> <Ev test="speedyspec-wp-password-php::php::override_ends_with_the_request"/> An exception your method throws reaches the caller unchanged. <Ev test="speedyspec-wp-password-php::php::throwing_override_surfaces_as_php_exception"/> See the architecture page.
