## How they are verified

- **WordPress's own tests.** WordPress's password tests (`authPassword.php`, `wpRand.php`) run against the native functions in the embedded PHP. All pass except five, listed in the test on purpose: the phpass and MD5 checks, and three that tune bcrypt's cost while argon2id is the default. <Ev source="ss:crates/speedyspec-wp-password-php/tests/wordpress.rs#L19-L30" hash="bd25750da7897a1d9172599f83d9d1fda688ca4a230302c7e31a313d14c50e98"/> <Ev test="speedyspec-wp-password-php::wordpress::wordpress_password_tests_pass_but_divergences"/> WordPress's sodium tests (`fileSignature.php`, `wpVerifyFastHash.php`) all pass except the phpass one. <Ev test="speedyspec-wp-crypto-php::wordpress::wordpress_crypto_tests_pass_but_phpass"/>
- **Recorded cases.** `compat/password/cases.json` and `compat/crypto/cases.json` hold what WordPress 7.1.5 answered on PHP 8.5.12. The Rust rules and the PHP functions replay them: every recorded check, except the formats SpeedySpec rejects on purpose, and every fast hash, verification and signature check. <Ev test="speedyspec-wp-password-php::php::recorded_checks_replay"/> <Ev test="speedyspec-wp-password::rehash::rehash_replays_recorded"/> <Ev test="speedyspec-wp-password::random::rand_replays_recorded_ranges"/> <Ev test="speedyspec-wp-crypto-sodium::recorded::fast_hashes_match"/> <Ev test="speedyspec-wp-crypto-sodium::recorded::verifications_match"/> <Ev test="speedyspec-wp-crypto-sodium::recorded::signatures_match"/>
- **PHP's behaviour.** Signatures, defaults, filter order and arguments, `$wp_hasher`, and PHP's own errors match WordPress. <Ev test="speedyspec-wp-password-php::php::signatures_match_wordpress"/> <Ev test="speedyspec-wp-password-php::php::filters_fire_in_wordpress_order"/> <Ev test="speedyspec-wp-password-php::php::wp_hasher_honoured"/> <Ev test="speedyspec-wp-crypto-php::php::signatures_match_wordpress"/> <Ev test="speedyspec-wp-crypto-php::php::message_hooks_fire_only_with_their_error_and_in_wordpress_order"/>

The server keeps no `breaks.json` for these areas; its documented differences are the expected failures above and the notes in each crate.

## Differences

- **argon2id is the default.** `wp_hash_password()` writes `$argon2id$` hashes (through libsodium) unless `wp_hash_password_algorithm` says otherwise; WordPress writes `$wp$2y$`. Both verify. <Ev source="ss:crates/speedyspec-wp-password/src/hash.rs#L18-L20" hash="76079bff4cbe6cb27b64f55b51c76e0634e9cc044cb9265b39ae9dd5cc63fe27"/> <Ev test="speedyspec-wp-password-php::php::round_trip_with_php"/>
- **argon2 hashes the trimmed password**, as WordPress's bcrypt does; WordPress's argon2 hashes it untrimmed. <Ev test="speedyspec-wp-password::hash::default_is_argon2id_trimmed"/>
- **Old hashes never verify:** raw MD5 (32 characters or fewer), phpass `$P$`, `$2x$`, and `crypt()`-only formats (MD5-crypt, SHA-256-crypt, SHA-512-crypt). The user resets their password. `wp_verify_fast_hash()` never verifies a phpass hash either. <Ev test="speedyspec-wp-password::check::md5_rejected_even_when_hash_matches"/> <Ev test="speedyspec-wp-password-bcrypt::vectors::refuses_2x"/> <Ev test="speedyspec-wp-crypto::core::verify_rejects_unprefixed_and_phpass"/>
- **Cost limits.** A stored bcrypt or argon2 hash whose cost is above the site's limits never verifies and is never computed, and hashing above them is PHP's `ValueError`. The defaults are bcrypt cost 16 and argon2 256 MiB with 10 passes. <Ev source="ss:crates/speedyspec-wp-password-contracts/src/lib.rs#L187-L212" hash="c19e776f555047f2203acd57a7e5e55a9bd7b4ae958e29ca008412ff1ef526db"/> <Ev test="speedyspec-wp-password::check::bcrypt_above_the_cost_limit_never_verifies_nor_runs"/> <Ev test="speedyspec-wp-password-php::php::php_bound_cost_limits_cap_hashing_and_checking"/>
- **`password_hash()`'s ignored-salt warning** is raised as an `E_USER_WARNING`; PHP raises an `E_WARNING`. The message is PHP's. <Ev source="ss:crates/speedyspec-wp-password-php/src/lib.rs#L18-L20" hash="ed004c66cd0e97986f4603b4c9ce7d54083aabdc5d30810ed6482cf4cda7d436"/> <Ev test="speedyspec-wp-password-php::php::php_errors_match"/>
- **`verify_file_signature()`** never returns `signature_verification_unsupported`: the runtime always has ext-sodium and sha384. <Ev source="ss:crates/speedyspec-wp-crypto-php/src/lib.rs#L13-L14" hash="1ddd9359643835ccc764343a75efb0d00056a6c0971af16516df295bce64bb78"/>

## Replacing them

Each pluggable function is a port in the service container. Where WordPress lets a plugin declare `wp_hash_password()` first, SpeedySpec lets PHP bind its own object under `SpeedySpec\WpPassword\PasswordHasher` (and the other ports) for the request; Rust callers then get it too. <Ev test="speedyspec-wp-password-php::php::php_override_replaces_default"/> <Ev test="speedyspec-wp-password-php::php::rust_callers_get_the_php_override"/> <Ev test="speedyspec-wp-password-php::php::override_ends_with_the_request"/> The sodium functions have no port; see the architecture page.
