## Behaviour

Native: `post.php`'s `register_post_type()` is a line of PHP over `SpeedySpec\WpPosts\Native\register_post_type`. <Ev source="ss:crates/speedyspec-wp-posts-php/src/post-types.php#L49-L52" hash="c60da1861b33f0315ca403af925d5d1674d7b65c12770903604aa8ecb1f7bf69"/> <Ev source="ss:crates/speedyspec-wp-posts-php/src/registry.rs#L258-L337" hash="16b1902e58c51e7282942080a64ad7aae12efa6bf8c9c2b10543f900a6d28fa3"/>

It parses `$args`, checks the name, runs the `register_post_type_args` and `register_{$post_type}_post_type_args` filters and `post_type_labels_{$post_type}`, resolves the object with phase 2's rules, applies the features and meta capabilities to PHP's globals, and builds `WP_Post_Type` without its constructor with the resolved properties. The steps of unported seams stay the class's own methods (`add_rewrite_rules()`, `register_meta_boxes()`, `add_hooks()`, `register_taxonomies()`). Then `registered_post_type` and `registered_post_type_{$post_type}`. The registries have no handler in the container: they are PHP's globals (`$wp_post_types`, `$wp_post_statuses`, `$_wp_post_type_features`), read and written live, so a handler would only wrap the global and there is nothing to rebind. ## The Rust rules

`check_post_type_name` is the name rule: `sanitize_key()` without its filter, then `NameLength` when the result is PHP-`empty()` (`""` or `"0"`) or longer than 20 bytes. `"Book Type!"` registers as `booktype`, and an integer-like name such as `"123"` works. The error carries WordPress's code and message, and `NAME_LENGTH_VERSION` is the `_doing_it_wrong()` version, `4.2.0`. <Ev source="ss:crates/speedyspec-wp-posts/src/key.rs#L5-L25" hash="a756000485a6717c3dd4fd670d87843a41c45924a39f3f78172c440ab66c2465"/> <Ev test="speedyspec-wp-posts-contracts::values::errors_carry_wordpress_codes_and_messages"/>

`PostTypeRegistry::register` is the rest: it builds the object as `new WP_Post_Type()` does (`resolve_post_type`), remembers its meta capabilities, runs `add_supports()`, stores it (in its old place when the name is already registered), and returns the actions and taxonomies for the adapter: `add_meta_boxes_{$post_type}` when `register_meta_box_cb` is set, `future_{$post_type}`, and each value of an array `taxonomies`. <Ev source="ss:crates/speedyspec-wp-posts/src/registry.rs#L246-L254" hash="b57142023dbe6972237ca930455c55b16b3a56941a123b92bc9ca1b180fb3e99"/> <Ev source="ss:crates/speedyspec-wp-posts/src/registry.rs#L62-L73" hash="1628bea29c8386281db8dc045967aaab7076600cc91c3c6acb30fde15a7fd304"/>

The 12 recorded post type scenarios (38 calls, 21 of them `register_post_type()`) replay as in WordPress 7.2-RC2: each call's result, `_doing_it_wrong()` messages, actions added and removed, taxonomies and `$post_type_meta_caps`, and the whole of `$wp_post_types`, `$_wp_post_type_features` and `$wp_post_statuses` at the end. They cover bad names, each form of `supports`, a meta box callback, taxonomies, registering again, and unregistering, including two types that share a capability type. <Ev test="speedyspec-wp-posts::recorded::post_type_scenarios_match_wordpress"/> <Ev test="speedyspec-wp-posts::registry::re_register_keeps_position_and_old_features"/> <Ev test="speedyspec-wp-posts::registry::integer_like_name_is_a_string_key"/>

## Limits

- Recorded from WordPress 7.2-RC2 under the recorder's stubs: `__()` and `_x()` return their text, the rewrite functions do nothing, `register_taxonomy_for_object_type()` only notes its call, and `get_object_taxonomies()` returns nothing. <Ev source="ss:compat/posts/record.php#L53-L66" hash="6398e7220fdfb100a72b707de8a1729a005479e3dd92f38f53c6da72f86a0d8d"/>
- The rewrite rules, permastructs and query vars it adds belong to the rewrite seam.
- Unrecorded approximations: a non-array `capabilities` counts as empty, where PHP throws in `array_merge()`; an array `capability_type` missing index 0 or 1 gives `""` in the capability names; a non-empty `supports` that is neither an array nor an object adds no features. <Ev source="ss:crates/speedyspec-wp-posts/src/post_type.rs#L9-L17" hash="16d705e34605f277b0ce21a2867ff9b05605ce89c0bb79df47ed7016db112ba3"/> <Ev source="ss:crates/speedyspec-wp-posts/src/registry.rs#L16-L23" hash="05b8af77a2c25780103154def08c2580ce16d0c682d85a29b4536a0938a7002a"/>
- A `stdClass` inside `$args` crosses as a copy (any other object stays itself), so a `register_post_type_args` callback that hands one in gets an equal object back on the post type, not the same one.
