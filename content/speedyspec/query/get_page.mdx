## Behaviour

Native: `post.php`'s `get_page()` is a line of PHP over `SpeedySpec\WpPosts\Native\get_page`, which dispatches the `GetPostObject` message to the handler bound at `SpeedySpec\WpPosts\GetPostObjectHandler`, so a handler PHP binds there takes the call. <Ev source="ss:crates/speedyspec-wp-posts-php/src/posts.php#L90-L93" hash="a785dded0c0d91c423724221866b71a93e29c9da31aba50f84807c0ec6b8ab72"/> <Ev source="ss:crates/speedyspec-wp-posts-php/src/read.rs#L972" hash="e36673da60f2e3c36f440aa595fbc2c21c04e4077205d92fa828d53665309690"/>

It is [get_post()](/speedyspec/query/get_post/) with the same arguments, as WordPress's `get_page()` is: the native table maps both names to one function. <Ev scenario="get-by-id" area="posts-read"/> <Ev scenario="get-array-a" area="posts-read"/> <Ev test="speedyspec-wp-posts-php::compat::main"/>
