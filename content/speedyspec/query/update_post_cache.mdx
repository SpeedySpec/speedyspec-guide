## Behaviour

Native: `post.php`'s `update_post_cache()` is a line of PHP over `SpeedySpec\WpPosts\Native\update_post_cache`, which dispatches the `UpdatePostCacheObjects` message to the handler bound at `SpeedySpec\WpPosts\UpdatePostCacheObjectsHandler`, so a handler PHP binds there takes the call. <Ev source="ss:crates/speedyspec-wp-posts-php/src/posts.php#L135-L138" hash="ef9f328cb92d14abfa753fe9bfe613b19daf7a1d20eddd2d1511594dae0928cd"/> <Ev source="ss:crates/speedyspec-wp-posts/src/read/cache.rs#L134-L136" hash="779d5b541f1658e94660652680213ab6fd388168e201efa436cf1a725c7a4f38"/> <Ev source="ss:crates/speedyspec-wp-posts-php/src/read.rs#L809-L817" hash="a27af75f6ddc0c802bbdd77fdd87d32b07a6c3c0823d82f60908da2191e702ed"/>

It writes each post to the `posts` group with `wp_cache_add_multiple()`, keyed by `ID` as PHP keys an array (`"5"` is 5), so an entry already cached stays. A post whose `filter` isn't `raw` is sanitized to `raw` in place first, as WordPress does through the object's handle. An empty argument does nothing. <Ev scenario="cache-update" area="posts-read"/> <Ev scenario="cache-update-keeps-existing" area="posts-read"/> <Ev scenario="cache-update-empty" area="posts-read"/> <Ev scenario="cache-update-wp-post" area="posts-read"/> <Ev test="speedyspec-wp-posts-php::compat::main"/> <Ev test="speedyspec-wp-posts-tests::read::update_post_cache_objects_key_string_ids_as_ints"/>
