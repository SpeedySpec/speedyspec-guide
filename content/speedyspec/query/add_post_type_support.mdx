## The Rust rule

`PostTypeRegistry::add_support` sets each feature to `true`, or to the extra arguments as a list when there are any; no features leaves the registry as it was. `add_supports()` hands it its calls as `SupportToAdd` values, so phase 4's adapter can make them against `$_wp_post_type_features` instead. <Ev source="ss:crates/speedyspec-wp-posts/src/registry.rs#L339-L341" hash="1061d87f16fd3acd77bb31080dbc5e40bfb5a4733f0603a63bb8a2857a943947"/> <Ev source="ss:crates/speedyspec-wp-posts/src/registry.rs#L90-L100" hash="ec41c27d03fae97906a9066ebbe82b92d9a5c4c0f29922ad0bf529d6a80cc4da"/>

The recorded `supports-api` scenario and the `lists` scenario replay as in WordPress 7.2-RC2, comparing `$_wp_post_type_features` in order. <Ev test="speedyspec-wp-posts::recorded::post_type_scenarios_match_wordpress"/> <Ev test="speedyspec-wp-posts::recorded::list_scenarios_match_wordpress"/>
