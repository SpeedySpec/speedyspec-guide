## Behaviour

Native: `post.php`'s `get_post_status()` is a line of PHP over `SpeedySpec\WpPosts\Native\get_post_status`, which dispatches the `GetPostStatus` message to the handler bound at `SpeedySpec\WpPosts\GetPostStatusHandler`, so a handler PHP binds there takes the call. <Ev source="ss:crates/speedyspec-wp-posts-php/src/posts.php#L45-L48" hash="51738213115c0a41cf9d804b1ab9e564b2396006803328eca1b74120a33e6850"/> <Ev source="ss:crates/speedyspec-wp-posts/src/read/get.rs#L390-L398" hash="a951340b5a83688bb6df36702f197ec5c9795915ea8c55dc514036a7da34d095"/> <Ev source="ss:crates/speedyspec-wp-posts-php/src/read.rs#L474-L499" hash="86b18a9ea8d4016360e7fcd91a71bb2d6f04bcb16fdf3cc5e2a4e98346f7ef4f"/>

It reads the post and follows WordPress's branches: `inherit` attachments take their parent's status (a trashed parent's `_wp_trash_meta_status`, else `publish` for a missing parent), an attachment's own status otherwise, then the `get_post_status` filter with `( $post_status, $post )`. With a trashed parent it reads the parent's status twice, as WordPress does. ## Differences

- **The meta statement.** This function reads post meta through the native meta functions, whose `update_meta_cache()` statement selects `meta_id` too (`SELECT meta_id, post_id, meta_key, meta_value …`, where WordPress sends `SELECT post_id, meta_key, meta_value …`), because the meta entity carries its id. A plugin that matches the exact text in a `query` filter misses it; the rows, the cache and the query count are WordPress's. It is the meta seam's documented difference, recorded here as a break on the scenarios that watch the statement. <Ev break="cache-prime-statement" step="1" area="posts-read"/> <Ev break="count-readable-statement" step="1" area="posts-read"/> <Ev source="ss:compat/posts-read/breaks.json#L1-L14" hash="c5f076b4794a20681d8b985e4d9fb2e12e1bda0c5f3b95a2ba59b4e080731c8d"/> See [update_meta_cache()](/speedyspec/meta/update_meta_cache/).
- **Objects in hook arguments are copies.** The use cases carry PHP values, and `PhpValueHooks` makes them PHP values on the way into a hook, so a callback gets an equal object of the same class, not the one WordPress would hand it. An object a callback returns crosses back as it is (a `stdClass` as an equal copy).
