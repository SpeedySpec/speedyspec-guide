## Behaviour

The PHP twin of the `PostRepository` port: `wp_posts`, with a method per `$wpdb` call `post.php` makes (`find`, `find_many`, `parent_ids`, `pages_by_names`, `all_page_ids`, `count_by_status`, `count_attachments`, `last_post_time`, `available_mime_types`, `insert` and the three slug owners) and `engine`. Values cross as PHP holds them: a post is a row array keyed by column, as `$wpdb->get_row( …, ARRAY_A )` gives it; ids are ints, names and types strings, and nothing is `null`. <Ev source="ss:crates/speedyspec-wp-posts-php/src/twins.rs#L1-L10" hash="4f78e74903ef43775cc01d27db7248ae809568fb7f7f51d24774abb5348b5ec2"/> <Ev source="ss:crates/speedyspec-wp-posts-php/src/twins.rs#L26-L59" hash="0ec0bdb24a7f68fb1e1ec3ddd87555a1f1d5abd3f92e1c1f9d6e1a7ce1d7b460"/>

## Override

Bind an object implementing it at `SpeedySpec\WpPosts\PostRepository` in the container. The use cases resolve the port on every call, so the binding applies for its request; a binding that throws, or an object that doesn't implement the interface, is an `Error` from the post function, and nothing falls back to SQL.
