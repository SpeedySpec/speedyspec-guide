## Behaviour

The PHP twin of the `Taxonomy` port, the taxonomy code the post functions call until the taxonomy seam is ported. The reads and the writes share one binding.

- **For the reads:** `update_object_term_cache()`, `clean_object_term_cache()` (from `_prime_post_caches()`, `update_post_caches()` and `clean_post_cache()`) and `post_term_fields()`, `WP_Post::__get()`'s `post_category` and `tags_input` branch (from `get_post_field()` and `wp_update_post()`).
- **For the writes:** `set_post_terms()` (`wp_set_post_terms()`), `object_taxonomies()`, `default_terms()` (the taxonomies with a `default_term`), `assign_terms_cap()` (the taxonomy's `assign_terms` capability, or `null` where `get_taxonomy()` is false), `get_object_terms()`, `get_the_terms()`, `is_object_in_taxonomy()`, which `wp_insert_post()` and `wp_update_post()` call, and `delete_object_term_relationships()` for the 5b writers.

## Override

Bind an object implementing it at `SpeedySpec\WpPosts\Taxonomy` in the container. The default binding is `PhpTaxonomy`, which calls WordPress's own functions. The use cases resolve the port on every call (`Resolved`, a Proxy, seen by the reads through their narrower port), so a binding made for the request applies, and a binding that fails is an `Error` from the post function with no fallback.
