## Behaviour

Served by WordPress's class. `register_post_type()` is native since phase 4 of the posts and meta port: it resolves the arguments with the Rust rules below and makes the object without its constructor, giving it the resolved properties, so `WP_Post_Type` stays WordPress's `class-wp-post-type.php`, and its methods (`set_props()`, `add_supports()`, the rewrite, meta box, hook and taxonomy steps) stay its own. <Ev source="ss:crates/speedyspec-wp-posts-php/src/registry.rs#L17-L21" hash="fa67d9da32ed419f5ca37cccf5eb486576436bd10f454faddf6d2b1747187894"/> <Ev test="speedyspec-wp-posts-php::registry::main"/>

## The Rust rules

`PostType` is a `WP_Post_Type` object's properties in `get_object_vars()` order, declared ones first; it knows nothing of how it is stored. `resolve_post_type` is the constructor and `set_props()`, `add_supports` and `unregistration` are the supports and removal methods, and `default_labels` is `get_default_labels()`. The declared properties include 7.2's `randomable` and `show_in_abilities`, in WordPress's order. <Ev source="ss:crates/speedyspec-wp-posts/src/post_type.rs#L72" hash="bfaed7dd67375117c06b58e63604ac1bb8a74f2103536322eac2fb450ca06186"/> <Ev source="ss:crates/speedyspec-wp-posts/src/post_type.rs#L95" hash="db3429a54ae58f4ac3087cf8c9f759106fc4c38a2615e788e7c986e7e44062ab"/> <Ev source="ss:crates/speedyspec-wp-posts-contracts/src/values.rs#L307-L313" hash="933246bb03fd9df9d5e260fbeddaeeac4ad6d9546a90914d34dbdbed12b2a085"/> <Ev source="ss:crates/speedyspec-wp-posts/src/post_type.rs#L1-L7" hash="ef835478ab76e7d0a7096814bb2ae3b147848d95c9be9bbf80e98117e6c456a5"/>

The methods that add hooks, rewrite rules or taxonomies don't run in Rust. The rules return the `add_action()` and `remove_action()` calls and the taxonomies, for phase 4's adapter to apply; rewrite rules belong to the rewrite seam and the REST controllers to the REST API. Each method's page says which.
