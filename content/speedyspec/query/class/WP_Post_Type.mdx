## Behaviour

Served by WordPress's PHP; the Rust rules below are not wired yet. The runtime worker links neither posts crate, so PHP on SpeedySpec runs WordPress's own `class-wp-post-type.php` until phase 4 of the posts and meta port. <Ev source="ss:crates/speedyspec-php-runtime/Cargo.toml#L24-L60" hash="4e45d1d171d753b4dfe1c47e78d7b37982c3572c9fc8cf407854fed9c53b58e9"/>

## The Rust rules

`PostType` is a `WP_Post_Type` object's properties in `get_object_vars()` order, declared ones first; it knows nothing of how it is stored. `resolve_post_type` is the constructor and `set_props()`, `add_supports` and `unregistration` are the supports and removal methods, and `default_labels` is `get_default_labels()`. The declared properties include 7.2's `randomable` and `show_in_abilities`, in WordPress's order. <Ev source="ss:crates/speedyspec-wp-posts/src/post_type.rs#L69" hash="bfaed7dd67375117c06b58e63604ac1bb8a74f2103536322eac2fb450ca06186"/> <Ev source="ss:crates/speedyspec-wp-posts/src/post_type.rs#L92" hash="db3429a54ae58f4ac3087cf8c9f759106fc4c38a2615e788e7c986e7e44062ab"/> <Ev source="ss:crates/speedyspec-wp-posts-contracts/src/values.rs#L215-L221" hash="933246bb03fd9df9d5e260fbeddaeeac4ad6d9546a90914d34dbdbed12b2a085"/> <Ev source="ss:crates/speedyspec-wp-posts/src/post_type.rs#L1-L6" hash="28f351def0346ad166666326bc06bcd8c4f5746e9e7427a99156980fa47a674c"/>

The methods that add hooks, rewrite rules or taxonomies don't run in Rust. The rules return the `add_action()` and `remove_action()` calls and the taxonomies, for phase 4's adapter to apply; rewrite rules belong to the rewrite seam and the REST controllers to the REST API. Each method's page says which.
