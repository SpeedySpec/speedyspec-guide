## Behaviour

Native: `post.php`'s `get_available_post_mime_types()` is a line of PHP over `SpeedySpec\WpPosts\Native\get_available_post_mime_types`, which dispatches the `GetAvailablePostMimeTypes` message to the handler bound at `SpeedySpec\WpPosts\GetAvailablePostMimeTypesHandler`, so a handler PHP binds there takes the call. <Ev source="ss:crates/speedyspec-wp-posts-php/src/posts.php#L180-L183" hash="1be774f7b2f7259995fb0f9415351ef2cfd32415bcf75dbe1829d205666099b6"/> <Ev source="ss:crates/speedyspec-wp-posts/src/read/counts.rs#L349-L352" hash="4fc25ea730c19873c517c9b9343a1b924534582f4ed7548e3968c3945fcf3697"/> <Ev source="ss:crates/speedyspec-wp-posts-sql/src/repository.rs#L578" hash="e8cafd687f60e19c65dcce776af07a88e4251afccb467bfaa5449329e49d52f7"/>

An array from `pre_get_available_post_mime_types` replaces the statement (`SELECT DISTINCT post_mime_type … WHERE post_type = %s`); then the falsy values are dropped and the rest renumbered. <Ev scenario="mime-available" area="posts-read"/> <Ev test="speedyspec-wp-posts-php::compat::main"/>

WordPress's own `Tests_Post_GetAvailablePostMimeTypes` tests, copied from 7.2-RC2, call it and pass against the port on a single site and on multisite. <Ev test="speedyspec-wp-posts-php::wordpress::wordpress_posts_runs_pass"/>

## Known breaks and open cases

- **Row order.** The statement has no `ORDER BY`, as in WordPress, so its rows come in the engine's order. The replay matches on MySQL 9.6; the run on CI's MySQL 8.4 is still to come (the server's CI last ran before the post functions were wired). If the order differs there, it becomes a documented break with its reason. <Ev source="ss:crates/speedyspec-wp-posts-sql/src/repository.rs#L1-L15" hash="02cf4d46a7902a0e90e131e8bd763989cf66225c4a7982286bc643a1e7d3ba3c"/>
