## Behaviour

Native: `post.php`'s `update_post_caches()` is a line of PHP over `SpeedySpec\WpPosts\Native\update_post_caches`, which dispatches the `UpdatePostCachesObjects` message to the handler bound at `SpeedySpec\WpPosts\UpdatePostCachesObjectsHandler`, so a handler PHP binds there takes the call. <Ev source="ss:crates/speedyspec-wp-posts-php/src/posts.php#L145-L148" hash="e7e1da73521020b39365efaeee9c1b61eacd8458ca4b819a185f33103823f674"/> <Ev source="ss:crates/speedyspec-wp-posts/src/read/cache.rs#L337-L341" hash="5db5691fb3cb74b3b2411ca6cba9a1072eed69e9a87c1faed49228266e514392"/>

It caches the posts with `update_post_cache()`; then, unless the type list is empty, their terms (a falsy type is `any`, and `any` means the posts' own types); then, when asked, their meta with `update_postmeta_cache()`. <Ev test="speedyspec-wp-posts-php::compat::main"/> <Ev test="speedyspec-wp-posts-tests::read::update_post_caches_caches_posts_terms_and_meta"/>

WordPress's own `Tests_Post_UpdatePostCache` tests, copied from 7.2-RC2, pass against the port on a single site and on multisite. <Ev test="speedyspec-wp-posts-php::wordpress::wordpress_posts_runs_pass"/>

## Differences

- **The meta statement.** This function reads post meta through the native meta functions, whose `update_meta_cache()` statement selects `meta_id` too (`SELECT meta_id, post_id, meta_key, meta_value …`, where WordPress sends `SELECT post_id, meta_key, meta_value …`), because the meta entity carries its id. A plugin that matches the exact text in a `query` filter misses it; the rows, the cache and the query count are WordPress's. It is the meta seam's documented difference, recorded here as a break on the scenarios that watch the statement. <Ev break="cache-prime-statement" step="1" area="posts-read"/> <Ev break="count-readable-statement" step="1" area="posts-read"/> <Ev source="ss:compat/posts-read/breaks.json#L1-L14" hash="c5f076b4794a20681d8b985e4d9fb2e12e1bda0c5f3b95a2ba59b4e080731c8d"/> See [update_meta_cache()](/speedyspec/meta/update_meta_cache/).
