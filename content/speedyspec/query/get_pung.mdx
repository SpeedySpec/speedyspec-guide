## Behaviour

Native: `post.php`'s `get_pung()` is a line of PHP over `SpeedySpec\WpPosts\Native\get_pung`, which dispatches the `GetPung` message to the handler bound at `SpeedySpec\WpPosts\GetPungHandler`, so a handler PHP binds there takes the call. <Ev source="ss:crates/speedyspec-wp-posts-php/src/posts.php#L75-L78" hash="52da9740326deb469a3d5029c6fe8f22392a5a63d730a0d0949e7a10b8536bd1"/> <Ev source="ss:crates/speedyspec-wp-posts/src/read/pings.rs#L70-L72" hash="fd1f3fd711871c802f7aa317456cb15e9fb6c5a44a8c8078cd04518aad2113b3"/>

It reads the post and splits its `pinged` on whitespace, dropping empties, then runs the `get_pung` filter. False when there is no post. <Ev test="speedyspec-wp-posts-php::compat::main"/> <Ev test="speedyspec-wp-posts-php::errors::main"/> <Ev source="ss:crates/speedyspec-wp-posts-php/tests/errors.rs#L151-L171" hash="d7f364bd335a351bc0174e5c05add07e4d3a4f80babccf08a3c916ea37a3712e"/>

WordPress's own `Tests_Post_Pings` tests, copied from 7.2-RC2, call it and pass against the port on a single site and on multisite. <Ev test="speedyspec-wp-posts-php::wordpress::wordpress_posts_runs_pass"/>

## Differences

- **An object argument is read as a copy.** The readers beside `get_post()` hand an object argument to the use case as a copy, for one dispatch. WordPress's `get_post()` inside them sanitizes a `stdClass` with no `filter` in place, setting `filter` to `raw` and casting its ids to int; on SpeedySpec the caller's object is left as it was. The answer is the same. Not recorded. <Ev source="ss:crates/speedyspec-wp-posts-php/src/read.rs#L30-L34" hash="2bc082f37a3aa63398531ebb37534e185fe71501b2fbacd16834877684966948"/>

## Limits
