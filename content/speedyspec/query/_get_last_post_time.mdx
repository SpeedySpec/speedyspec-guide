No copied WordPress test calls it directly. WordPress's `Tests_Post_GetLastPostDate` and `Tests_Post_GetLastPostModified` reach it indirectly, through `get_lastpostdate()` and `get_lastpostmodified()`, and those tests pass against the port on a single site and on multisite. <Ev test="speedyspec-wp-posts-php::wordpress::wordpress_posts_runs_pass"/>

## Server time

- **`server` time.** For `'server'` the statement reads the GMT column through `DATE_ADD( …, INTERVAL '0' SECOND )`, and MySQL answers with six fractional digits (`2024-03-01 20:00:00.000000`), which WordPress returns as it is and SpeedySpec does too. posts-contracts 0.3.1's repository suite expects that text, and the SQL repository appends `.000000` where another engine's translation answers without it, as the memory repository does, so every engine answers as MySQL. The suite runs plainly on MySQL and SQLite; there is no known break. <Ev source="ss:crates/speedyspec-wp-posts-sql/src/repository.rs#L574-L582" hash="1c3dafab5fe58fd95e13a989f9b270db0df61901cd6678e6c4228279a9a9ca15"/> <Ev test="speedyspec-wp-posts-sql::engines::server_time_keeps_mysql_fraction"/> <Ev test="speedyspec-wp-posts-sql::engines::suite_on_mysql"/> <Ev test="speedyspec-wp-posts-sql::engines::suite_on_sqlite"/>
