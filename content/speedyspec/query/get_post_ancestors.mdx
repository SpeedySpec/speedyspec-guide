## Behaviour

Native: `post.php`'s `get_post_ancestors()` is a line of PHP over `SpeedySpec\WpPosts\Native\get_post_ancestors`, which dispatches the `GetPostAncestors` message to the handler bound at `SpeedySpec\WpPosts\GetPostAncestorsHandler`, so a handler PHP binds there takes the call. <Ev source="ss:crates/speedyspec-wp-posts-php/src/posts.php#L30-L33" hash="a68b308571a94933c5cdda5845cd55c656c633e67e36ccd18227276c28ef57d9"/> <Ev source="ss:crates/speedyspec-wp-posts/src/read/get.rs#L278-L279" hash="82085ba01b0467001ea2ca05f21a7bb8d672d47f384b1178df3a4b5e443d224e"/>

It reads the post with `get_post()`, then each ancestor through the same cached read, and stops at a post with no parent, a missing post, the post itself, or an ancestor already listed. With no post it answers `array()`. The walk is phase 2's `post_ancestors` rule below, now over the `posts` cache. <Ev scenario="ancestors-nested" area="posts-read"/> <Ev scenario="ancestors-loop" area="posts-read"/> <Ev scenario="ancestors-missing-parent" area="posts-read"/> <Ev scenario="ancestors-self-parent" area="posts-read"/> <Ev scenario="ancestors-missing-post" area="posts-read"/> <Ev scenario="ancestors-object" area="posts-read"/> <Ev scenario="ancestors-cached" area="posts-read"/> <Ev test="speedyspec-wp-posts-php::compat::main"/>

WordPress's own `Tests_Post_Objects` tests, copied from 7.2-RC2, call it and pass against the port on a single site and on multisite. <Ev test="speedyspec-wp-posts-php::wordpress::wordpress_posts_runs_pass"/>

## Differences

- **An object argument is read as a copy.** The readers beside `get_post()` hand an object argument to the use case as a copy, for one dispatch. WordPress's `get_post()` inside them sanitizes a `stdClass` with no `filter` in place, setting `filter` to `raw` and casting its ids to int; on SpeedySpec the caller's object is left as it was. The answer is the same. Not recorded. <Ev source="ss:crates/speedyspec-wp-posts-php/src/read.rs#L30-L34" hash="2bc082f37a3aa63398531ebb37534e185fe71501b2fbacd16834877684966948"/>

## The Rust rule

`post_ancestors` takes the post already read and lists its parent, grandparent and so on. It stops at a post with no parent, a missing post, the post itself or an ancestor already listed, as WordPress's loop does, so a cycle in the table ends the walk. It reads each ancestor once through the `PostReader` port. <Ev source="ss:crates/speedyspec-wp-posts/src/hierarchy.rs#L136-L155" hash="ad950b6e41b5ba638e3d703de449d4d82240ac6380a813c1362ef5e5fd983f0b"/>
