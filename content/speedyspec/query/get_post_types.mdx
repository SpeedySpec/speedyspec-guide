## The Rust rules

`post_types` (objects) and `post_type_names` (names) filter the `PostTypes` port's list with `filter_object_list`, which is `wp_filter_object_list()` over `WP_List_Util::filter()`. An argument matches when the object has the property (`isset()`) and it is loosely equal, by PHP 8's `==`, to the wanted value: `'public' => 1`, `'1'` and `'yes'` all match `public => true`, and a null property never matches. Empty arguments return every entry whatever the operator; an unknown operator returns none. Each entry keeps PHP's array key, so `"123"` comes back as the int key `123`; `names` plucks each object's `name` property. <Ev source="ss:crates/speedyspec-wp-posts/src/list.rs#L1-L11" hash="751f912862323eae0a0c72f9a13944b8fcbeb8c1ac91bad75811940251b27c46"/> <Ev source="ss:crates/speedyspec-wp-posts/src/list.rs#L114-L121" hash="901c811955f72ed15726eddbc8090a5d2f0892b5373a6a656ec45428806c194c"/> <Ev source="ss:crates/speedyspec-wp-posts/src/list.rs#L140-L159" hash="7664f9a3f730bb710ce1c9a95001debec2dc0be383f25107925ddd42f476330e"/>

The recorded `lists` scenario's 34 `get_post_types()` calls and 6 more after `create_initial_post_types()` replay as in WordPress 7.1.5, with `and`, `or`, `not` and unknown operators, both outputs, and loose matches. <Ev test="speedyspec-wp-posts::recorded::list_scenarios_match_wordpress"/> <Ev test="speedyspec-wp-posts::recorded::initial_post_types_match_wordpress"/>
