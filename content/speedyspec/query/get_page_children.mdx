## Behaviour

Served by WordPress's PHP; the Rust rules below are not wired yet. The runtime worker links no posts crate, so PHP on SpeedySpec runs WordPress's own `post.php` until phase 4 of the posts and meta port. <Ev source="ss:crates/speedyspec-php-runtime/Cargo.toml#L24-L60" hash="4e45d1d171d753b4dfe1c47e78d7b37982c3572c9fc8cf407854fed9c53b58e9"/>

## The Rust rule

`page_children` is `get_page_children()`: the pages below a page, depth first, each parent's children in list order, a repeated ID listed each time it is reached. It reads no posts. <Ev source="ss:crates/speedyspec-wp-posts/src/pages.rs#L54-L60" hash="aaf07d84e68968a941c55e1b6446179092b36c3a70a149ea3c38f2978d016e60"/>

The 8 recorded calls over four lists (a tree given out of order, orphans, a repeated ID and an empty list) replay as in WordPress 7.2-RC2, comparing whole posts in order. <Ev test="speedyspec-wp-posts::entity::pages_match_wordpress"/> <Ev source="ss:compat/posts-entity/record.php#L673-L703" hash="5026e57fe2fa7b325dc8a288b27c3ced15287b61b165543066b2ad2a43773558"/>

## Limits

- Over a list with a cycle reachable from the start, WordPress's stack never empties. The rule stops at the first revisit: a page already on the path from the start is listed but not descended into. <Ev source="ss:crates/speedyspec-wp-posts/src/pages.rs#L1-L7" hash="dd1882ecd0e8a7351d700af6109b877be3813d96457fd5c53315f877b2b8b9e5"/>
- The rule returns copies of the posts; the adapter must hand back the `WP_Post` objects it was given.
