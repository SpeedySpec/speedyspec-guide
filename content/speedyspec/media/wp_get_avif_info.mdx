## Behaviour

Native. Returns all `false` unless `wp_get_image_mime()` says `image/avif`. Otherwise it takes the width, height, bit depth and channel count from PHP 8.5's `getimagesize()`, which reads them as WordPress's bundled libavifinfo does; when PHP can't size the file, it reads it through the media reader. <Ev source="ss:crates/speedyspec-wp-media-php/src/media.php#L145-L165" hash="948f453d362d7fc92333b02319bf6932828e6672f11138ca5d496a202972157a"/> <Ev test="speedyspec-wp-media-php::php::avif_info_matches_wordpress"/> It matches WordPress over the recorded image corpus, and WordPress's own AVIF tests pass against it. <Ev test="speedyspec-wp-media-corpus::images::image_corpus_matches_wordpress_except_listed_differences"/> <Ev test="speedyspec-wp-media-php::wordpress::wordpress_media_tests_pass"/>

The corpus holds no AVIF that PHP can't size (no grid AVIF), so the reader fallback is not compared with WordPress. Read from the source: that fallback reads only a local path, so for a stream-wrapper path PHP can't size the function returns all `false`, where WordPress parses the stream with libavifinfo. <Ev source="ss:compat/media/PROVENANCE.md#L62" hash="e12d10d7a3c3bf4f3839b9dbf9da71aa843914a0b89ea1ef9d734987c070b56f"/>
