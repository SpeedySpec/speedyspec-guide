## The crates

- **`speedyspec-wp-media-contracts`**: the reader port, `MediaReader`, and its answer, `MediaInfo`, which describes a file without reference to any library; the limits a read may take (`ProbeLimits`), why a read failed (`ReadError`), and the ports the rules reach other WordPress code through (`TagSanitizer` for kses, `TimeParser` for `strtotime()`, `ContentSniffer` for fileinfo). Plain data: no I/O, no serialization, no library types. <Ev source="ss:crates/speedyspec-wp-media-contracts/src/lib.rs#L5-L13" hash="a2b8ff32373bcfdeca1c82495d3f052d28326c54fef39cbfe279365c5b65a880"/>
- **`speedyspec-wp-media`**: WordPress's rules over the port: the getID3-shaped view, the audio, video and image functions, and the MIME tables. It depends only on the contracts. It also holds `SniffingReader`, which sends Standard MIDI Files to the MIDI reader and everything else to the general reader. <Ev source="ss:crates/speedyspec-wp-media/src/lib.rs#L1-L5" hash="e84fd3e8f849f747e0d7e19a1de5616c96e0a282e3589e9561f160f93af8865a"/> <Ev source="ss:crates/speedyspec-wp-media/src/sniffing.rs#L9-L14" hash="3a2b346815201d9b607c3287f5ce5cbce14f47524bf948bfc73790d5f9449bc0"/> <Ev test="speedyspec-wp-media::sniffing::midi_magic_goes_to_midi"/>
- **`speedyspec-wp-media-ffmpeg`**: the general reader. A C shim reads the file through libavformat within byte, time and stream limits, with no protocols and nested opens refused; a mapper turns what it found into `MediaInfo`, keeping FFmpeg's own view as the raw view. <Ev source="ss:crates/speedyspec-wp-media-ffmpeg/src/lib.rs#L1-L6" hash="469d2177f8cde66fdb7bc0c46fa8800a125fe99a7870165d0cd266b34b1e8ae7"/> <Ev test="speedyspec-wp-media-ffmpeg::reader::byte_limit"/> <Ev test="speedyspec-wp-media-ffmpeg::reader::symlink_is_refused"/>
- **`speedyspec-ffmpeg-sys`**: links the pinned, LGPL-only static FFmpeg once for the runtime. <Ev source="ss:crates/speedyspec-ffmpeg-sys/src/lib.rs#L1-L6" hash="9e19877179a1631d3f7695ce4f0e17555a38ad81b8b175c21b7c539ad6ac7a59"/> <Ev test="speedyspec-ffmpeg-sys::link::licence_is_lgpl_2_1_or_later"/> <Ev test="speedyspec-ffmpeg-sys::link::nothing_reaches_the_network_or_other_files"/> <Ev test="speedyspec-ffmpeg-sys::link::every_demuxer_is_reviewed"/>
- **`speedyspec-wp-media-midi`**: a bounded Standard MIDI File reader, since FFmpeg has none: the duration from the tempo map, and text events as tags. <Ev source="ss:crates/speedyspec-wp-media-midi/src/lib.rs#L1-L5" hash="43d727fadcf5cdd94d472c43b61e5c1bc93cd633dffdc2396a71a4ecde782a8b"/> <Ev test="speedyspec-wp-media-midi::midi::format1_merges_tempo_track"/>
- **`speedyspec-wp-media-isolate`**: `IsolatedReader` runs the readers in a short-lived, limited child; `CachedReader` puts the shared result cache in front. <Ev source="ss:crates/speedyspec-wp-media-isolate/src/lib.rs#L1-L6" hash="c07647133c891f2ed3d59f4bfe2fb3bd23e35b555e5aa50a84ee7206fada751c"/>
- **`speedyspec-wp-media-php`**: the PHP area. It binds the reader, registers the port PHP may replace, and declares the functions. <Ev source="ss:crates/speedyspec-wp-media-php/src/lib.rs#L1-L19" hash="0861979e7c4de7bf6fb708584b4c071a30ac113445119a29df0e72f9dbdd6ef5"/>
- **`speedyspec-wp-media-corpus`** and **`speedyspec-wp-media-testkit`** are for tests only: the corpus comparisons with WordPress, and small media files built in code.

## The contracts

- **`MediaReader::read(source, limits)`**: read a file, given as a path or an open descriptor, within the limits. Bound under `SpeedySpec\WpMedia\MediaReader`, which is also the PHP twin's name. <Ev source="ss:crates/speedyspec-wp-media-contracts/src/reader.rs#L10-L11" hash="38f3c42f9880e2605173652a5138f8e7ee42ccf551ed7a2383a6f23ce02dec39"/> <Ev source="ss:crates/speedyspec-wp-media-contracts/src/reader.rs#L102-L105" hash="e052085821b859ebcef12e223d22fa85029bb2c8ad371863e323f16dfa42d8ee"/> <Ev test="speedyspec-wp-media-contracts::contracts::media_reader_key_is_the_php_interface"/>
- **`ReadError`** is a Special Case each rule maps to `false` or a partial array: not found, unrecognized, truncated, a limit exceeded, timed out, I/O, crashed.

## The use cases

- **Read audio or video metadata**: read through the port, then build WordPress's array from `MediaInfo` and run the `wp_read_audio_metadata` or `wp_read_video_metadata` filter. The filter's fourth argument is the getID3-shaped view, with the neutral description under `speedyspec`. <Ev test="speedyspec-wp-media-php::php::filter_sees_four_arguments_and_wins"/> <Ev test="speedyspec-wp-media-php::php::speedyspec_key_has_schema_1"/>
- **Copy ID3 data** (`wp_add_id3_tag_data()`) and **find the creation time** (`wp_get_media_creation_timestamp()`): pure rules over arrays. <Ev test="speedyspec-wp-media-php::php::add_id3_tag_data_leaves_other_values_alone"/>
- **Type and size an image**: sniff the first 64 bytes; for every type PHP's `getimagesize()` reads, ask PHP; for the rest, read through the port. <Ev test="speedyspec-wp-media::images::fast_path_types"/> <Ev test="speedyspec-wp-media-php::php::getimagesize_fast_path_is_phps"/>
- **Describe WebP and AVIF**: WebP from its first 40 bytes, as WordPress does; AVIF from PHP's `getimagesize()`, falling back to the port. <Ev test="speedyspec-wp-media::images::webp_info_lossy_lossless_vp8x"/> <Ev test="speedyspec-wp-media::images::avif_info_fields"/>
- **List MIME types and check a file's type**: WordPress's tables plus the formats the reader reads, and the content type `wp_check_filetype_and_ext()` compares with, which is fileinfo's unless the reader must decide between audio and video. <Ev source="ss:crates/speedyspec-wp-media/src/mime.rs#L373-L380" hash="c9c1d5c79ed40a0659d8412b0362c63a1362878f5e5cf1014fcc97992e1763c5"/> <Ev test="speedyspec-wp-media::content_mime::reader_rescues_audio_only_matroska"/> <Ev test="speedyspec-wp-media::content_mime::non_media_claim_never_reads"/>

## The adapters and the container key

- **The default reader.** The worker builds `CachedReader` over `IsolatedReader`, whose child is the runtime binary's hidden `media-probe` command, and binds it under the key with `MediaArea::bind_defaults()`. Without its own binary, it binds a reader that always fails. <Ev source="ss:crates/speedyspec-php-runtime/src/worker.rs#L65-L98" hash="2181ba57d692c61e1cbb370a9fc49949acd2ba18a4c3d216cef51ca43d7959f2"/> <Ev source="ss:crates/speedyspec-wp-media-php/src/lib.rs#L66-L73" hash="0afcc1c965a6f5ec8b9c46de1ad30493e639c35a264644ae63cfc3625dd366cd"/> <Ev test="speedyspec-wp-media-isolate::isolated::reads_through_the_child"/>
- **The cache's store** is a Caching Store: files under the site's `cache/speedyspec-media`, or memory when the app has no site directory. Entries last 30 days, and each worker keeps up to 256 decoded results in memory in front of the store. <Ev source="ss:crates/speedyspec-php-runtime/src/worker.rs#L48-L63" hash="46f7218a245b9ca36f0808dafd3c437d60fe7f86e0220402d1814df886501ec3"/> <Ev test="speedyspec-wp-media-isolate::cached::second_read_hits_the_local_cache"/> <Ev test="speedyspec-wp-media-isolate::cached::store_errors_do_not_fail_reads"/> <Ev test="speedyspec-wp-media-isolate::cached::paths_outside_the_root_are_not_cached"/>
- **PHP replacement.** `MediaArea::ports()` registers the port, so a PHP object bound under it reaches Rust callers as a `PhpReplacement`; its array must be the neutral array, schema 1, or the file reads as unreadable. <Ev source="ss:crates/speedyspec-wp-media-php/src/lib.rs#L75-L81" hash="b5d311e928cf3483144da5e94ac46bfffbfc925e10ff0004e610e57c6b4955d6"/> <Ev source="ss:crates/speedyspec-wp-media-php/src/twins.rs#L5-L9" hash="9cbd9dad2ea92491a85c3423842e35e46a7341d6db73cdd194fb5bbca26ab4eb"/> <Ev test="speedyspec-wp-media-php::php::malformed_php_reader_array_is_unreadable"/> <Ev test="speedyspec-wp-media-php::php::php_reader_exception_propagates"/>
- **PHP.** Tag values go through PHP's `wp_kses_post()`; fileinfo is PHP's `finfo_file()`, its handle kept per request; the `wp_read_*_metadata` filters run through the Hook API and are skipped without entering PHP when nothing is attached. <Ev test="speedyspec-wp-media-php::php::fileinfo_handle_is_kept_per_request"/>
- **The facade.** `media.php` declares the functions at the start of every request, each in a `function_exists` guard. A path through a stream wrapper (an offload plugin's `s3://`) is copied to a temporary file first, up to the read's byte limit. <Ev source="ss:crates/speedyspec-wp-media-php/src/media.php#L6-L51" hash="1b597493c296efd5dbcff383de2ab9aaa44a4dbc516bc184e1121c2de88d047f"/> <Ev test="speedyspec-wp-media-php::php::stream_wrapper_path_is_copied"/>

## Patterns

- **Ports and Adapters**: `MediaReader`, with FFmpeg, MIDI and PHP readers as adapters; `MediaInfo` is the domain's own description of a file.
- **Protection Proxy**: `IsolatedReader` runs each untrusted read in a limited child.
- **Decorator**: `CachedReader` in front of any reader.
- **Strategy** and **Composite**: `SniffingReader` chooses a reader by the file's first bytes.
- **Data Mapper**: the FFmpeg mapper turns libavformat's findings into `MediaInfo`.
- **Virtual Proxy**: filetype checks resolve the reader only when a read is needed.
- **Special Case**: each `ReadError` maps to WordPress's `false` or partial array.
- **Registry** (the container) and **Facade** (`media.php`).

## How to change this

- **Replace the reader from PHP:** implement `SpeedySpec\WpMedia\MediaReader` in a class whose `read( $path )` returns the neutral array or `false`, and bind the class name (not a closure), for one request or in `app.<id>.php.bindings`. To add to what the default reads, call `SpeedySpec\WpMedia\Native\read_media( $path )` inside it:

  ```php
  \SpeedySpec\Container\Container::getInstance()->bind(
      \SpeedySpec\WpMedia\MediaReader::class,
      My_Plugin_Media_Reader::class
  );
  ```

- **Replace it from Rust:** pass another `MediaReader` to `MediaArea::bind_defaults()`. Keep untrusted reads in a child: wrap a new library in `IsolatedReader`, and put `CachedReader` in front.
- **Add a MIME type:** use WordPress's `mime_types` or `upload_mimes` filters, as on WordPress.
- **What must still pass:** WordPress's media tests and the corpus comparisons, with every allowed difference listed in `compat/media/*differences.json` and explained in `compat/media/DIFFERENCES.md`. <Ev test="speedyspec-wp-media-php::wordpress::wordpress_media_tests_pass"/> <Ev test="speedyspec-wp-media-corpus::corpus::every_difference_is_still_needed"/>

## Calling it from Rust

A runtime feature that needs a file's duration resolves the port, so it reads through the isolated, cached reader (or a PHP replacement):

```rust
use std::path::PathBuf;
use std::time::Duration;

use speedyspec_container::Container;
use speedyspec_wp_media_contracts::{MEDIA_READER, MediaReader, MediaSource, ProbeLimits};

/// How long an uploaded audio or video file plays, or `None` when it can't be read.
fn play_time(container: &Container, path: PathBuf) -> Option<Duration> {
    let reader = container.make_port::<dyn MediaReader>(MEDIA_READER).ok()?;
    reader.read(MediaSource::Path(path), &ProbeLimits::default()).ok()?.duration
}
```
