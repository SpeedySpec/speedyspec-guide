Mostly not in SpeedySpec yet. Of `media.php`'s functions, the runtime answers three natively: `wp_getimagesize()`, `wp_get_webp_info()` and `wp_get_avif_info()`. ## Reading untrusted files

Uploads are untrusted, so the worker never parses one itself. Each read the cache can't answer runs in a fresh child, a copy of the runtime binary started with its hidden `media-probe` command: no environment, the file as standard input and nothing else open, resource limits, its own process group, and on Linux a seccomp filter. The child is killed at its deadline and always reaped. <Ev source="ss:crates/speedyspec-wp-media-isolate/src/isolated.rs#L32-L33" hash="c9d16f0ce4f427cb5fea581d0a6e6852a7352f53f1f99dac06b4be7d68046730"/> <Ev test="speedyspec-wp-media-isolate::isolated::deadline_kills_a_loop"/> <Ev test="speedyspec-wp-media-isolate::isolated::memory_limit_stops_runaway_allocation"/> <Ev test="speedyspec-wp-media-isolate::isolated::inherited_descriptors_are_closed_in_the_child"/> <Ev test="speedyspec-wp-media-isolate::isolated_fds::no_zombies_or_fd_leaks"/>

A read may take 64 MiB of the file, 5 seconds, 1 GiB of memory and 32 streams; larger pictures and tag values are dropped. <Ev source="ss:crates/speedyspec-wp-media-contracts/src/reader.rs#L39-L51" hash="2eb94b581e30bc8b8535cde8476c97e1ad70a391a4b2311384d892d964c9c110"/> <Ev test="speedyspec-wp-media-contracts::contracts::default_limits_match_the_spec"/>

Results go into a shared cache, so plugins that read a file's facts on every page view don't start a child each time. The key is the file's path under the app, its size, its modification time and a hash of its first 64 KiB, so a changed file misses. The worker keeps the store in files under the site's `cache/speedyspec-media`, shared by its workers, or in memory when the app has no site directory. <Ev source="ss:crates/speedyspec-php-runtime/src/worker.rs#L48-L63" hash="46f7218a245b9ca36f0808dafd3c437d60fe7f86e0220402d1814df886501ec3"/> <Ev source="ss:crates/speedyspec-wp-media-isolate/src/cached.rs#L95-L134" hash="b65e4b364d1bd7ff83bcaa2367a56ce46ead1af88fbc30fc78348db27121cba4"/> <Ev test="speedyspec-wp-media-isolate::cached::another_worker_hits_the_shared_store"/> <Ev test="speedyspec-wp-media-isolate::cached::changed_file_misses"/> Failures are cached too: those the same bytes always produce for the full time, timeouts and crashes for five minutes. A missing file is never cached. <Ev source="ss:crates/speedyspec-wp-media-isolate/src/cached.rs#L30-L33" hash="9c0768119dcd8d77bba05653df32c411a140343ff4838b9d029804df2d93c5e2"/> <Ev test="speedyspec-wp-media-isolate::cached::deterministic_errors_are_cached"/> <Ev test="speedyspec-wp-media-isolate::cached::transient_errors_are_cached_briefly"/>

## How it is verified

- **WordPress's own tests.** WordPress's media tests that cover these functions (`imageSize.php`, `webpAvifInfo.php`, `metadata.php`, `wpAddId3TagData.php`, `mimeFunctions.php`, `wpGetMimeTypes.php`, `wpCheckFiletype.php`) all pass against the native functions. <Ev test="speedyspec-wp-media-php::wordpress::wordpress_media_tests_pass"/>
- **Recorded corpora.** `compat/media` records WordPress 7.2-RC2 on PHP 8.5.12, with its bundled getID3 1.9.28, over a corpus of audio, video and image files. The native functions match it except where a difference is listed with its reason, and a listed difference that stops differing fails the test. <Ev test="speedyspec-wp-media-corpus::corpus::corpus_matches_wordpress_except_listed_differences"/> <Ev test="speedyspec-wp-media-corpus::images::image_corpus_matches_wordpress_except_listed_differences"/> <Ev test="speedyspec-wp-media-corpus::images::every_image_difference_is_still_needed"/> <Ev test="speedyspec-wp-media-php::mime::filetype_checks_match_wordpress_except_listed_differences"/> <Ev test="speedyspec-wp-media-corpus::uploads::uploads_match_wordpress_except_listed_differences"/>

## Differences

- **Images.** For every type PHP 8.5's `getimagesize()` reads, `wp_getimagesize()` returns PHP's own answer and `wp_get_avif_info()` takes its figures from it. JPEG XL, QOI, PCX, PPM/PGM, SGI and Radiance HDR, for which WordPress returns `false`, are typed and sized through FFmpeg. <Ev source="ss:compat/media/DIFFERENCES.md#L46-L57" hash="bfdc0f2a6da2c0abf672dee2e096a2f151a1131a5a0240335cf5fb960e05284b"/>
- **Metadata.** Tags are copied from every tag format, not only ID3; bitrates, encoder options, some codec names and Latin-1 tags differ with the library; formats getID3 can't read get full metadata. <Ev source="ss:compat/media/DIFFERENCES.md#L15-L44" hash="f428ca52e6b9c7eb6b802632c40c7550a61794a392363bf2e8b980b4059ef0e0"/>
- **MIME list.** `wp_get_mime_types()` is WordPress's list unchanged, in order, plus a row for each format the reader reads (`jxl`, `qoi`, `m2ts`, `opus`, `aiff` and others), so those uploads are accepted. <Ev source="ss:compat/media/DIFFERENCES.md#L59-L66" hash="5fa550f0d720b383cfa18ad15f467e68981dd19c98a6fdd7bee6eb9ab9a2b094"/> <Ev test="speedyspec-wp-media-php::mime::wordpress_lists_are_kept"/> <Ev test="speedyspec-wp-media-corpus::uploads::every_added_row_is_read"/>
- **Filetype checks.** `wp_check_filetype_and_ext()` is WordPress 7.2's function. Its content type is fileinfo's, except when fileinfo and the extension name different kinds of media (an audio-only Matroska that fileinfo calls video): then the reader decides, and accepts the file if it holds the kind the extension claims. Documents, files pretending to be media, and every upload WordPress accepts are judged as WordPress judges them. <Ev source="ss:compat/media/DIFFERENCES.md#L109-L134" hash="fafa08906106408d414b996ff8e9ca81cb34a2282fecdc3a62fdae5eadade4c4"/> <Ev test="speedyspec-wp-media-php::php::audio_only_matroska_is_accepted"/> <Ev test="speedyspec-wp-media-php::php::html_named_mp3_is_rejected"/> <Ev test="speedyspec-wp-media::content_mime::reader_never_overrides_non_media_fileinfo"/>

## Replacing the reader
