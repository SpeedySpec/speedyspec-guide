## Behaviour

Native: the `UpdateMetadataByMid` command. It reads the row, unslashes, runs the `update_{$meta_type}_metadata_by_mid` short-circuit, sanitizes, renames the key when `$meta_key` is given, writes, clears the cache, and fires `update_{$meta_type}_meta` with the value before sanitizing and `updated_{$meta_type}_meta` after, plus the old post hooks. <Ev scenario="mid-post" area="metadata"/> <Ev scenario="mid-comment" area="metadata"/> <Ev scenario="mid-term" area="metadata"/> <Ev scenario="mid-invalid" area="metadata"/> <Ev scenario="mid-short-circuit" area="metadata"/> <Ev scenario="mid-update-slashed-and-sanitized" area="metadata"/> <Ev test="speedyspec-wp-meta-php::wordpress::wordpress_meta_runs_pass"/>

## Differences

- **`site` on a single site** reads or writes `wp_sitemeta`, where WordPress has no table and returns false; see [_get_meta_table()](/speedyspec/meta/_get_meta_table/). <Ev source="ss:crates/speedyspec-wp-meta-sql/src/repository.rs#L409-L412" hash="29a136921eb9b816414883ee9065616182ae0208fb47091146cd9f6e5179566a"/>
