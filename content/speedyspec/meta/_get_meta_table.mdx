## Behaviour

Native. It answers `$wpdb->{$type}meta`, or false when the type has no table. Native wpdb answers for WordPress's tables, and a table a plugin declares as a dynamic property (`$wpdb->thingmeta`) is read from PHP. `blog` has no table on a single site, as in WordPress. <Ev scenario="add-unknown-type" area="metadata"/> <Ev scenario="add-unique-thing" area="metadata"/> <Ev scenario="add-blog-meta-multisite" area="metadata"/> <Ev test="speedyspec-wp-meta-sql::engines::unknown_type_has_no_table"/> <Ev test="speedyspec-wp-meta-sql::engines::single_site_has_no_blogmeta"/> <Ev test="speedyspec-wp-meta-sql::engines::multisite_has_blogmeta"/> <Ev source="ss:crates/speedyspec-wp-meta-php/tests/errors.rs#L114-L119" hash="46237dc3182ffd716df5a4cad016ad72c39aae40174b216ff320640746c50875"/>

## Differences

- **`site` on a single site** is `wp_sitemeta`, where WordPress's `$wpdb->sitemeta` is unset and the answer is false. So on a single site every meta function given `'site'` reads or writes `wp_sitemeta` where WordPress returns false. The options seam's network code relies on that table name. <Ev source="ss:crates/speedyspec-wp-db/src/contract.rs#L9-L18" hash="50cf694ed9e009bbef4e2f33680c81b4a234952e78670d7e3773a87cce54931d"/>
