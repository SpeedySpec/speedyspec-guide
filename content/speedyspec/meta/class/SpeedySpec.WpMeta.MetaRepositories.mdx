## Behaviour

The PHP twin of the `MetaRepositories` port, which is `_get_meta_table()` as a factory. Its one method, `for_type( $meta_type )`, returns a `SpeedySpec\WpMeta\MetaRepository` for the type, or `null` when the type has no table. `#[php_port]` declares it at the start of every request from the Rust trait, so the two can't drift. <Ev source="ss:crates/speedyspec-wp-meta-php/src/twins.rs#L1-L9" hash="81fd2e76b297139d5fd4fd71d4f419654e653bfdb6868bfa339b9c0c71bf3fd5"/> <Ev source="ss:crates/speedyspec-wp-meta-php/src/twins.rs#L24-L27" hash="8da0296377662a7b634ff4f1e210927a1c7e54ed079f945f39c2abe771130091"/>

## Override

To keep meta somewhere other than the meta tables, bind a class implementing this interface under `SpeedySpec\WpMeta\MetaRepositories`. Every metadata function then reads and writes through it, for PHP and Rust callers, until the request ends; a type it answers `null` for has no table.
