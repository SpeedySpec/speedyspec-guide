## Behaviour

Native: the `UpdateMetaCache` command. After the `update_{$meta_type}_metadata_cache` short-circuit it skips ids already cached, drops entries that aren't arrays, loads the rest in one query in id order, and adds an entry for every id, an empty array when it has no meta. <Ev scenario="cache-several-ids" area="metadata"/> <Ev scenario="cache-partly-cached" area="metadata"/> <Ev scenario="cache-invalid" area="metadata"/> <Ev scenario="cache-short-circuit" area="metadata"/> <Ev scenario="cache-post" area="metadata"/> <Ev scenario="cache-user" area="metadata"/> <Ev scenario="cache-thing" area="metadata"/> <Ev scenario="cache-switch-to-blog-multisite" area="metadata"/> <Ev test="speedyspec-wp-meta-tests::use_cases::update_meta_cache_queries_only_the_uncached"/> <Ev test="speedyspec-wp-meta-tests::use_cases::update_meta_cache_collapses_duplicate_ids"/> <Ev test="speedyspec-wp-meta-php::wordpress::wordpress_meta_runs_pass"/>

## Differences

- **The query text.** The repository returns `Meta` entities, which carry their id, so the statement adds the id column.
