## Behaviour

Served by WordPress's PHP; the Rust rules below are not wired yet. The runtime worker links no meta crate, so PHP on SpeedySpec runs WordPress's own `meta.php`. <Ev source="ss:crates/speedyspec-php-runtime/Cargo.toml#L20-L55" hash="955f1ccec24cc11da3fa0826db96868561c6e6c3cdc55277b37b80c09b513508"/>

## The Rust rules

`register_meta()` is split at its `register_meta_args` filter. `prepare_registration` is the steps before it: a callable `$args` becomes the legacy sanitize form, and a callable `$deprecated` becomes the `auth_callback`. <Ev source="ss:crates/speedyspec-wp-meta/src/register.rs#L161-L188" hash="2ec8cb7bd63be47f2f90c7dd2d3ff0cc42ac25d4b0cecea17bea359128b25213"/> `resolve_registration` is everything after it, in PHP's order: the REST item schema for array meta, the revisions checks, the `auth_callback` fallback to `is_protected_meta()`, the sanitize and auth filters, then the default's type check. It returns what to do: store the key and add filters, add filters only (the legacy forms), or reject with WordPress's `_doing_it_wrong()` message. <Ev source="ss:crates/speedyspec-wp-meta/src/register.rs#L41-L65" hash="f8dbbf1a32177a5b1cce731978ee4afcfe7ce04e03f8be73eb5c60f9a4931bcd"/>

All 21 recorded scenarios replay as in WordPress 7.1.5: each call's result, its `_doing_it_wrong()` messages, the filters it added and removed, and the whole `$wp_meta_keys` after it. They cover defaults, subtypes, unknown arguments with and without the allowed list, array meta in REST, revisions, a default of the wrong type, protected keys, named callbacks and both legacy forms. <Ev test="speedyspec-wp-meta::recorded::register_matches_wordpress"/> <Ev source="ss:compat/meta/record.php#L241-L300" hash="def625ae92458b875b8d93ac99a8a7fce53f1c9d6615430d8c78899a33f8c27c"/>

## Limits

- Recorded under the recorder's stubs of `post_type_supports()` and `rest_validate_value_from_schema()`, not WordPress's real post types or schema check. <Ev source="ss:compat/meta/record.php#L40-L50" hash="15dcefe9533a32dcbf7c2c2f47c16192fd1dd0013fccea36df2804ff42359d62"/>
- The `register_meta_args` filter itself runs only in phase 3.
- A float `object_subtype` is truncated to an int, where PHP's hook name keeps the decimals; an array or object one becomes `""`, and a non-array `show_in_rest.schema` isn't merged, where PHP throws. No recording covers these. <Ev source="ss:crates/speedyspec-wp-meta/src/register.rs#L8-L11" hash="310ef5b575de773d054537b2377e84efac7e4d509127781c54cc4c0064b182bd"/>
